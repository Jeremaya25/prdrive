# Agent scheduling: planner, network-return probes, `watch = true`

Files: `common/planificador.py` (pure), `common/red.py`, `common/huella.py`, `common/avisos_carpeta.py`, `common/moderacion.py`, `agente.py`.
Formerly AGENTS.md «The resident agent» bullets on the planner, #67 and #61. Core of the agent: `agent.md`.

## Planner (`common/planificador.py`)

Pure; it holds every rule: single queue; urgent («Sincronizar ahora») skips all moderation; pause / battery / power saving / metered hold everything, except that a metered network lets the keychain through (below); `intervalo · 2^k` backoff capped at 4 h (never below the interval); mode `sync` = infinite interval; offline remotes are PROBED (`SONDA`, an `rclone lsd remote:` with `catalog.NET_FLAGS`) instead of retried.

- A `RED` result doesn't count a failure; the agent probes at once and, if the remote answers, re-records it as `FALLO` (the classification was wrong). The suspicion is **per pair** (`Agente.sospechas`, `(root, pair)` → `Sospecha`): two pairs of one remote failing before its probe both get re-recorded; a non-`RED` result for that pair closes it; a pair whose mark is no longer the one the `RED` left (`Sospecha.tras`) is not touched.
- **Power saving** (`Politica.pausar_ahorro_energia`, on by default, `agente.json` → `moderacion`) holds passes and `watch` walks even on mains: the user (or the OS, on low battery) asked for it. `moderacion.energia()` reads it with the battery: Windows `SYSTEM_POWER_STATUS.SystemStatusFlag == 1` (battery saver; `energia_de_windows()` is the pure translation, and it counts on a desktop with no battery), Linux power-profiles-daemon's `ActiveProfile == "power-saver"` on the system bus (`org.freedesktop.UPower.PowerProfiles`, then the pre-0.20 `net.hadess.PowerProfiles`; `tuned-ppd` answers the first). No daemon, no saving. Whether Windows 11's «Energy saver» sets that flag is unverified (E1 in the checklist). runsync's service does not moderate at all.
- **A metered network does not hold the keychain** (`pl.deja_pasar()`, the one rule; `Pareja.llavero`, set by `agente.leer_servicio()`): it weighs nothing and is what matters most to have current. `decidir()` drops every other pair (and the probes of remotes only they use) and keeps going; `a_recorrer(motivo=…)` walks only it. Pause, battery and power saving still hold it: `moderacion()` checks them first, so their reason is another. The decision keeps `retenido` even when it carries the keychain's task, so the diary says «no se lanza nada salvo el llavero: red de uso medido» once instead of flapping with every keychain pass.
- Network needles live in `moderacion.ERRORES_DE_RED`; `sync.KNOWN_ERRORS` uses `moderacion.es_de_red` as a **callable needle**: one list, because the agent doesn't carry `sync.py`.

## An offline remote is probed when the network comes back (#67)

Not on a blind timer. `common/red.py` (`AvisosDeRed`; Tk-free, its own thread on Linux, none on Windows, **independent of the tray**: `agente.poner_red()`, an indirection point) hears the system and each notice becomes a `PIDE_CAMBIO_DE_RED` in the agent's queue. Cite the APIs like `common/dbus.py` cites its spec. Sources:

- **Windows**: `NotifyNetworkConnectivityHintChange` (iphlpapi, netioapi.h; **Windows 10 2004, build 19041, or later**: an older one lacks the export, `AttributeError`, no notices), with `NL_NETWORK_CONNECTIVITY_HINT` **by value** in the ctypes callback, notifying on the levels that mean some network (`NIVELES_CON_RED`: local, internet, captive portal). Cancelled with `CancelMibChangeNotify2` from the agent thread, never from the callback (its docs: deadlock); `ApiWindows` keeps the `WINFUNCTYPE` alive until then.
- **Linux, rtnetlink** (`RTMGRP_IPV4_IFADDR | RTMGRP_IPV6_IFADDR`, no privileges): `Direcciones` dumps the address list first (silent), then notifies only for a **new** global, non-tentative address (a network back, a VPN interface up, a cable plugged). A DHCP/RA renewal repeats a known address and says nothing. Kernel-level, so it works without NetworkManager (networkd, ifupdown, iwd…): no networkd-specific source is needed.
- **Linux, NetworkManager** on the system bus: `StateChanged(u)` into 50/60/70 (`NM_CONECTADO`, `NMState`); it sees a captive portal letting through (SITE → GLOBAL) with no address change. `NameOwnerChanged` tracks it going and coming back; without it, netlink stays.

The burst is coalesced in the planner (`pl.CambioDeRed`, `cambia_la_red()`, `red_asentada()`): one probe per offline remote `ASENTAR_RED` (5 s) after the last notice, at most `TOPE_RAFAGA_RED` (30 s) after the first, and **not while a task is in flight** (a failing probe would push its next one to the fallback and swallow the notice). A burst with no offline remote is dropped silently. `pl.sondear_ya()` is the one «probe now» for this, «Probar ahora» and `despertar`.

**The timer stays, as the fallback**: `pl.sondeo(politica, avisa_la_red)` is `Politica.sondeo_de_respaldo` (30 min, the service's default interval) while a source is `activa`, `sondeo_sin_conexion` (5 min, as before) otherwise. The trade-off, said out loud: what no notice sees waits up to 30 min: the remote coming back with nothing changed on this host (the NAS powered on), a VPN on Windows that leaves the connectivity level as it was, a captive portal on Linux without NetworkManager, or a source that subscribed fine and never fires. «Probar ahora» in the tray is the shortcut.

`agente.log` says at start what is heard; `estado.json` carries `cambios_de_red` and `agente.py status` prints it. Unverified on real hardware (N1–N8 in the checklist); the rtnetlink half was seen against this machine's real kernel only (a new address notifies, a renewal does not).

## A pair with `watch = true` is synced soon after its LOCAL files change (#61)

Instead of waiting for the interval. Agent only (runsync's service never looks), opt-in per pair, and only where the local side is a source (`Mode.origen_local`: bisync, up, up-mirror). `model._leer_watch()` rejects the rest at parse time (and `[defaults]` carrying `watch`: it is read from `[[pair]]` only, so there it would do nothing and look like it watched every pair). The agent, which reads the raw TOML, asks the same rule without raising (`model.pide_watch()`; `Servicio.locales` keeps each watched pair's `local`, normalised as the engine does it, `model.normalizar_local()`: `sync-data\docs` syncs, so that is the folder to look at).

- **Notices first, walking as the fallback** (spec `docs/superpowers/specs/2026-10-06-watch-con-avisos-design.md`, plan `docs/superpowers/plans/2026-10-06-watch-con-avisos.md`: phase 1 Linux, phase 2 Windows).
  - **Linux, inotify** (`common/avisos_carpeta.py`, `Inotify`, by `ctypes`; `agente.poner_avisos_carpeta()` opens it at start and says in `agente.log` which of the two the host does). One descriptor per agent, one watch per folder, mask `IN_CLOSE_WRITE | IN_ATTRIB | IN_CREATE | IN_DELETE | IN_MOVED_FROM | IN_MOVED_TO | IN_DELETE_SELF | IN_MOVE_SELF` added with `IN_ONLYDIR | IN_DONT_FOLLOW | IN_EXCL_UNLINK`; never `IN_MODIFY` (the close is enough; the price: a file written and never closed, a VM disk, is seen only when closed). It says whether a pair's folder changed, as one `Aviso` per pair: `CAMBIO`; `DESBORDADO` (a folder moved in or out, or `IN_Q_OVERFLOW`: counts as a change AND the agent re-arms the pair, `Agente.rearmar`; `vigilar()` is idempotent and sweeps watches the tree no longer reaches); `PERDIDA` (the pair's folder deleted or moved, `IN_UNMOUNT`, or no room for a new subfolder: the engine drops the pair and the agent walks it). Several in one turn keep the gravest. A folder created inside is armed inline (watch first, then `scandir`).
  - **Overlap**: `inotify_add_watch` on an inode the descriptor already watches returns the same `wd`, so a `local = "."` pair and a `sync-data/docs` pair share the docs subtree (`wd → {pairs}`); `dejar()` removes a watch only when no pair needs it. The top-level ignore (`IGNORAR_CAMBIOS`, `ruido_en()`) applies per pair, only to events in that pair's root watch, and ignored folders get no watch at all. `IN_ATTRIB` on a folder is not a change (the photo counts folders by name only).
  - **Not armed** (the pair walks; `Agente.sin_avisos` keeps why, `agente.log` and the root's `daemon.log` say it once): a network or host-shared filesystem (`avisos_carpeta.DE_RED`, from the longest mount point in `/proc/self/mountinfo`, `sistema_de()`: other machines' changes never notify); past `PRESUPUESTO` (half of `fs.inotify.max_user_watches`, which is PER USER and shared with the user's editor; the agent never takes more); `ENOSPC`; the folder missing. No entry cap with notices; the walk keeps its own.
  - **Arming runs on the `Muestreo` thread** (`Mirar.armar`): a cold USB stick takes seconds. The engine's maps take a lock per watch added, never across a `scandir`; `dejar()` during `vigilar()` cancels it (`DEJADA`, nothing left behind). A result for a pair no longer served, or from an older `Conexion`, is dropped and its watches left. Arming ignores moderation: it is what lets notices be recorded while moderation holds (the pass leaves as soon as it releases, its calm long over).
  - **Draining**: `Vigia.oir()` puts the descriptor in the agent's `poll`; when readable, `leer()` empties it at once and it is muted for `CALLAR_AVISOS` (0.25 s). It never ends the wait: a copy of thousands of files does not turn `vuelta()` thousands of times, and a `vuelta()` that raises or returns early cannot leave a readable descriptor making `poll` spin. A `leer()` that raises is unregistered and said once.
  - **The pass's own writes**: notices during a pair's pass set its `cambio`, which `pl.tras_pasada()` clears when the pass ends; `_rehacer_foto()` then `descartar()`s what is still queued (a dropped `DESBORDADO` still re-arms; a `PERDIDA` is never dropped).
  - **«Expulsar» and «Bloquear»** call `dejar_raiz()` right before releasing the root (`_soltar_avisos()`): measured unnecessary on Linux (unmounting with watches works; the kernel drops them with `IN_UNMOUNT`/`IN_IGNORED`), done so both systems keep one order. A root that stops being served, (re)connects or goes leaves its watches too.
  - **Windows, `ReadDirectoryChangesW`** (`ReadDirectoryChanges`; every call through `avisos_carpeta.Win32`, which tests replace). One directory handle per pair (`FILE_LIST_DIRECTORY`, shared read/write/delete, `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OVERLAPPED`), `bWatchSubtree`, `FILE_NOTIFY_CHANGE_FILE_NAME | DIR_NAME | SIZE | LAST_WRITE`: the system follows new and moved folders, so re-arming an armed pair is a no-op. One watcher thread issues EVERY read (none belongs to the short-lived `Muestreo` thread; `vigilar()` asks it through a request list and a control event and waits, `ESPERA_HILO`), waits on `WaitForMultipleObjects` (so at most `MAX_PAREJAS_WINDOWS`, 63, pairs; past that the pair walks) and re-issues each read at once, so it never wakes the agent. 0 bytes or `ERROR_NOTIFY_ENUM_DIR` is `DESBORDADO`; any other read error, `PERDIDA`. The top-level ignore filters on the notice's first path component.
  - **The open handle and ejecting** (spec question 1, accepted 06/10/2026). Each handle is registered with `RegisterDeviceNotificationW(DBT_DEVTYP_HANDLE)` on the tray window; if that fails the handle is closed and the pair walks, and with no tray `poner_avisos_carpeta()` opens no engine. The tray hands `DBT_DEVICEQUERYREMOVE`/`…FAILED`/`REMOVEPENDING`/`REMOVECOMPLETE` of a handle to `ReadDirectoryChanges.dispositivo()` (`Bandeja.dispositivo`, `Api.handle_de()`) BEFORE answering Windows: `QUERYREMOVE` closes the handle there and then (`CancelIoEx` + `CloseHandle`; the event and buffer live until the cancelled read completes) and the pair goes quiet, neither notified nor walked, since the drive is leaving; `QUERYREMOVEFAILED` re-opens it through the watcher thread; `REMOVEPENDING`/`REMOVECOMPLETE` is `PERDIDA`.
  - **Not on Windows**: a network folder (`GetDriveTypeW == DRIVE_REMOTE`) and a VeraCrypt volume (`QueryDosDeviceW` of its letter starting with `\Device\VeraCryptVolume`, VeraCrypt's `NT_MOUNT_PREFIX`; this covers the host root and a stick opened with «Abrir PRDRIVE»): spec question 2, whether VeraCrypt's dismount (`FSCTL_LOCK_VOLUME`) sends `DBT_DEVICEQUERYREMOVE` first, is unchecked (checklist F18); until then they walk.
- **The walk** (`common/huella.py`) is what a pair without notices does. `de_carpeta()` runs `os.scandir` over the pair's folder (no file opened, no link followed) and returns `planificador.Huella(entradas, firma, cortada)`: a sum of one hash per entry (relative path, size, `mtime_ns`), **not** the newest mtime or the total size, which a rename or a same-size swap leaves still. Folders count by name only (their mtime moves with things that are not content).
  - **Its pace** (`pl.cada_cuanto()`): every `sondeo` (10 s) during `sondeo_quieto` (120 s) after the last change seen (`Vigilada.movida`, set by a changed photo or a notice, never by a baseline or a pass), every `sondeo_quieto` otherwise (a freshly connected quiet pair included); on battery never under `sondeo_bateria` (60 s). The keychain always walks at `sondeo`: a handful of files, and the most important thing to keep current. The price: a change after a quiet spell is seen up to 2 min later.
  - `.prversions/` and `.prdrive/` at the top of the folder are not looked at (`agente.IGNORAR_CAMBIOS`: a `local = "."` pair would otherwise be fired by what each pass writes into `state/`). When the folder IS the device root (`local = "."`) neither is the OS noise at its top (`model.RUIDO_DEL_SISTEMA` through `agente.ruido_en()`: `System Volume Information`, `$RECYCLE.BIN`, `.Trash-<uid>`…, matched without case; the list `install/device.RUIDO` is built from, so the two cannot drift). The same rule (`huella.se_ignora()`) filters notices.
  - A SUBFOLDER `scandir` cannot open (`PermissionError`, which Windows gives for `System Volume Information`) is skipped by name and its contents are not looked at; only the folder itself failing voids the photo (`None`).
- **A pair can carry its own interval** (`Pareja.intervalo`, `pl.intervalo_de()`): it wins over the root's for its passes, its backoff and whether it is watched, so on a `sync`-mode root (infinite interval) only such a pair is walked. Only the keychain uses it, while its KeePassXC is open (`llavero.md`).
- **The rules are pure** (`PoliticaCambios`: `sondeo` 10 s, `sondeo_quieto` 120 s, `sondeo_bateria` 60 s, `calma` 20 s, `separacion` 120 s, `tope_entradas` 20 000; `observar`, `avisado`, `tras_pasada`, `toca_por_cambios`, `cada_cuanto`, `a_recorrer`; `Vigilada.avisos` marks a pair that hears notices and is never walked). `decidir()` brings the pair's pass forward to `max(cambio + calma, ultimo_intento + separacion)` when that is earlier than its interval: an ordinary pass flagged `Tarea.por_cambios`, **not** an urgent one, so pause, battery and metered network hold it like any other. A burst is one pass (each change moves the calm); a failing pair keeps its growing wait; one never tried is due anyway.
- **Walking and arming never block `vuelta()`** (~20 000 entries on a USB stick take seconds). `Agente._vigilar()` asks `pl.a_recorrer()` what to walk (not while moderation holds passes, since walking would spend what moderation wants to save; not the pair whose pass is running); a `Muestreo` takes the photos on a thread through `hilo()` (indirection point; at most ONE in flight) and the next turn `_recoger_fotos()` feeds them to `pl.observar()`.
  - The folder goes through `en_la_raiz()` on that thread: a `local` that `..` or a link takes out of the root is abandoned, said once, never walked. The photo itself is `agente.huella_local()` (indirection point, wraps `huella.de_carpeta()`).
  - While a walk of a root is in flight the thread holds its folder open, so «Bloquear» waits for it (`_mirando()`, up to `ESPERA_VENTANA`; then VeraCrypt asks before forcing, as ever). A walk that hangs (a network folder) keeps the one-at-a-time slot: no other pair is walked until it returns, and the interval rules meanwhile.
- **Served means what it means for passes.** Only roots in `_raices()` with `Conexion.motivo == ""` are walked: not a root paused from its window (#64), with a runsync window open (or inside its `GRACIA`), with another service holding the lock, being locked, nor the cut pair of `cortada`. What was remembered of a pair that stops being served is DROPPED, so the first photo after it comes back is a baseline and whatever changed meanwhile (the window syncs by itself) fires nothing; a root that disconnects loses all of it (`_olvidar_vigiladas()`). `urgentes` ignore all of this.
- **The pass's own writes must not fire it.** When a pair's pass ends (`_fin_de_pasada()` → `_rehacer_foto()`) its memory goes back to «baseline pending» (`pl.tras_pasada(v, None, ahora)`, asked at once), and any photo of that pair that was in flight when the pass ended (`Muestreo.descartar`), arrives while its pass runs, or comes from an earlier connection of the root (`Mirar.con`) is thrown away. The price, said out loud: what the person changes WHILE the pass runs, and in the turn or two until the new baseline, is absorbed into it and waits for the interval.
- **The walk's cap.** Past `tope_entradas` a walked pair is abandoned for this connection: said once in `agente.log` and in the root's `daemon.log` (`pl.se_abandona`); the interval rules. `de_carpeta()` cuts at the cap and says so with `Huella.cortada` (not «signature 0»), so finding out is cheap.
- **A watch that cannot see says so.** A photo that comes back `None` is «not a change», which on its own is what a quiet folder looks like. `Vigilada.fallidas` counts the walks in a row without a photo (`PoliticaCambios.fotos_fallidas`, 3): the third is one line in `agente.log` and the root's `daemon.log` (`pl.se_queda_sin_foto`), and the first good photo after it another (`pl.vuelve_a_haber_foto`). A pass does not reset the count (it proves nothing about the agent reading the folder), so a dead watch is told once per connection, not once per pass.
- **Known limit: sticky abandonment.** Inside one connection an abandoned pair stays abandoned (the folder may have shrunk, the agent will not know until the root reconnects), and `Mirar.con` does not notice a root remounted at another letter while a walk was in flight: at most a swallowed change or an extra pass.
- **Not seen**: remote changes (they wait for the interval), changes made during a pass, and any root not served in `daemon` mode (`sync` mode has an infinite interval: nothing to bring forward).
- `resumen()`/`estado.json` carry `vigila`, `vigila_abandonada` (names) and `vigila_recorre` (pair → why it walks; with no engine every watched pair, `agente.SIN_MOTOR_DE_AVISOS`) per unit, and `agente.py status` prints them («Recorre su carpeta (sin avisos del sistema): …»). `tests/test_watch_pareja.py` covers the model, the photo and the rules; `tests/test_avisos_carpeta.py` the engine against the real kernel (changes, overlap, moves, loss, budget, `ENOSPC`, unmounting a tmpfs with watches when run as root, `Vigia.oir()`); `tests/test_agente_watch.py` the wiring, with a fake photo, a fake engine (`AvisosFalsos`), the real one on Linux and a fake clock. `tests/test_bandeja_windows.py` covers the tray handing device events over. The Windows engine's logic runs everywhere against a fake `Win32`; its real-Windows checks run only on Windows (CI). Unverified on real hardware: see the checklist (F1–F19: walk cost, exFAT's 2 s mtime, VeraCrypt, network folders, inotify on exFAT/FAT32 sticks, ejecting with watches on both systems, Windows without tray, question 2).
