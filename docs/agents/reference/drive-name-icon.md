# The drive's name and icon (`common/autorun.py` + `common/explorador.py` + `ui/volumen.py` + `ui/tk_volumen.py`)

Formerly AGENTS.md «The drive's name and icon».

«Ajustes» → «Nombre e icono» sets what Windows Explorer shows for the drive via the root's `autorun.inf`: `label=` and `icon=` are still read on arrival though AutoRun has run nothing from removable media since Windows 7. No admin, any filesystem, accents allowed; the filesystem label is untouched. Seen on real hardware only for the traveler's file (M1 in the VeraCrypt results): it shows **after replugging**, and the window says so.

- **The file is edited, never rewritten.** `autorun.con()` replaces `label`/`icon` under `[autorun]` and keeps every other line; `autorun.sin()` drops only the keys its caller names. `traveler.write_autorun()` edits too: it keeps an existing label, a non-VeraCrypt icon and every foreign line; re-points a VeraCrypt icon at the executable the drive carries now (`vestibulo.traveler_ejecutables()`; `autorun.ICONOS_VERACRYPT` also recognises the old `VeraCrypt\VeraCrypt.exe`); and **removes** the `action=` / `shell\montar…` / `shell\desmontar…` it used to write (Windows ignores them on a removable drive (M2) and they pointed at an exe the portable lacks). UTF-16 + CRLF like VeraCrypt's own; `buscar()` matches the name case-insensitively. Nothing left → file deleted.
- **Which root**: always `DEVICE_ROOT`, the volume that holds the data. Unencrypted it is the drive plugged in; with BitLocker, the unlocked volume (the same one); with VeraCrypt, the **mounted** volume. The container's physical root (the vestibule's, `vestibulo.raiz_fisica()`) is **never written** (owner's decision): it is the USB stick, and it keeps whatever name and icon it has (the traveler's, or one written there by an earlier prdrive). `Estado.fuera` carries it only so the window can say so. The window prints the path it writes to.
- **With VeraCrypt on Windows, Explorer never reads the mounted volume's `autorun.inf`** (#63, Windows 11 build 26100, 15/10/2026: the volume's `MountPoints2\{GUID}` entry has no `_Autorun`, the shell gives `imageres.dll,-35` and the filesystem label; the physical stick's file *is* read). What it does read, for any letter and without admin, is `HKCU\Software\Classes\Applications\Explorer.exe\Drives\<L>\DefaultIcon` and `\DefaultLabel` (default value: the icon's **absolute** path, the name). `HKCU\…\Explorer\DriveIcons\<L>\DefaultIcon` is ignored by the shell (VeraCrypt's own `/m label=` writes `DriveIcons\%s\DefaultLabel`, a different key: no clash). So `common/explorador.py` copies `label=`/`icon=` there; `autorun.inf` stays the one source.
  - **Only a VeraCrypt volume's letter**: `explorador.de_veracrypt(L)` = `QueryDosDeviceW("L:")` starts with `\Device\VeraCryptVolume` (`NT_MOUNT_PREFIX`; no disk touched), and only where a prdrive device lives (its control file's id). Unencrypted drives (undiagnosed) and BitLocker (its padlock wins over any icon) get nothing. `icon=` is passed only as an existing file inside the root, relative, no `..`, no comma.
  - **Ownership by a marker**: each subkey written carries a `PRDRIVE` value = the device id, written before the default value. A subkey without it is someone else's and is never written or deleted; `Drives\<L>`, `Drives` and `Applications\Explorer.exe` are deleted only when left empty (`_podar()`); `Applications` never.
  - **Written** by `explorador.poner(raiz, app)`: by `cifrado.nombrar_letra()` (`explorador.limpiar()` then `poner()`, and nothing at all unless `DEVICE_ROOT` is a VeraCrypt letter): the main window runs it in a thread right after its first paint (`VentanaPrincipal.nombrar_letra()`, never before: the modules it loads would count against `modulos.main`), and the service at start (`runsync.daemon_main()`); the `.bat` and penwatch start prdrive one of those two ways. Also, by the agent on connecting a listed, accepted drive (`Agente._conectar()`, with `APP_SUBDIR`), and on save (`volumen.guardar()`, after the file and `recoger()`; never raises, the file is already the truth). A change calls `explorador.avisar_shell()` (`SHChangeNotify(SHCNE_UPDATEITEM, SHCNF_PATHW, root)`) for an Explorer window already open.
  - **Removed** by `explorador.quitar(raiz, id)`: the window's «Expulsar» right after launching the script (`cifrado.olvidar_letra()`: if the dismount then fails the letter shows the generic icon until prdrive starts again), the agent's `_desconectar()` (eject, «Bloquear», the volume vanishing), and `Expulsar PRDRIVE.bat`'s `:olvidar_letra` once it sees the container closed (`LETRA` noted before `/dismount`; `reg query … /v PRDRIVE | find "%ID%" && reg delete` per subkey; only vestibules rewritten by step 5 or «Añadir plataformas…» have it). `explorador.limpiar()` (whenever prdrive starts from a VeraCrypt volume) removes the orphans: a marked subkey whose letter is no longer a VeraCrypt volume or no longer holds that id (closed from VeraCrypt, unplugged; a stale `DefaultIcon` keeps pointing at the missing file).
  - **Nobody removes them when the volume closes with no prdrive running** (logged off, shut down, dismounted from VeraCrypt, a crash, the agent stopped or self-updating): the agent's connections live in memory, so `_desconectar()` never ran. The next ordinary pendrive to take that letter would show the old name and icon. So `explorador.limpiar()` also runs from the agent: `Agente._limpiar_letras()` at its first turn, beside `_limpiar_navegador("al arrancar")` (#157), and from `_recorrer()` whenever a letter that the previous walk did not see appears in `candidate_roots` (`Agente.letras_vistas`; not every turn; the first walk is only the baseline, the start-up call has just run). It passes `APP_SUBDIR`, since the agent's own `APP_DIR` is its folder, never raises, and logs the letters it cleaned in the diary. Safe from there: it only touches subkeys carrying `MARCA`, keeps those of a live VeraCrypt volume holding the same id, and a letter that is not a VeraCrypt volume is cleaned without reading the disk.
  - **`limpiar()` tells Explorer** (`avisar_shell(raiz_de(L))` for each letter it cleaned) so an open «Este equipo» window repaints the letter.
  - **Accepted caveat**: if `fleet.device_id()` gives `""` for a live VeraCrypt volume (a transient `OSError` reading its control file) at the moment `limpiar()` looks, that volume counts as an orphan and its keys go until the next `poner()` (reconnecting, opening prdrive from it or saving the name). Nothing retries it by itself.
  - The window says it (`Estado.letra`, from `explorador.letra_veracrypt()` in `volumen.leer()`): `cuando_se_ve()` → «enseguida en «Este equipo» (en una ventana ya abierta, al pulsar F5)», and `como_se_lee()` replaces «Windows lee de ahí el nombre y el icono» with why prdrive passes them. Otherwise the change shows when the drive is connected or, inside a container elsewhere, *opened* (`cuando_se_ve()`).
- **Where the icon lives**: `Estado.carpeta`, always `.prdrive/` (`icon=.prdrive\icono-verde.ico`, from `APP_DIR.name`, not hard-coded), so the root holds only `autorun.inf`. A prefixed icon loose on a root (`.prdrive-icono-verde.ico`, `autorun.PREFIJO_RAIZ`) is no longer written but still recognised: `recoger()` collects one on the root it writes to, and `device.es_ruido()` counts it as noise on a physical root that still carries one (hashed names cannot sit in the `RUIDO` set). There is no «VeraCrypt icon» option: the traveler lives on the physical root, so a mounted container has no executable to point at; a VeraCrypt `icon=` found on the root reads as `OTRO` (kept on a name-only save).
- **The choice is read back from `icon=` itself**, no separate state (the recognition lives in `common/autorun.py`: `CLAVES_MARCA`, `CLAVE_PROPIA`, `icono_nuestro()`, `clave_icono()`; `volumen.clave_de()`/`emblema()`/`recoger()` delegate to it, and `tests/test_volumen.py` pins `icons.CAMPOS == autorun.CLAVES_MARCA == volumen.MARCAS` keys): the icon file name carries the key (`icono-verde.ico`), a user's `.ico` a hash slice (`icono-propio-<8 hex>.ico`), and counts only where prdrive would put it (bare inside `.prdrive/`, or prefixed loose on the root). A new drawing is a new name because Explorer caches icons by path; `recoger()` then deletes our other icons, at the root too (this moves an old root icon into `.prdrive/` on the next save). An `icon=` prdrive did not write reads as `OTRO` and survives a name-only save.
- **The name is the device's name too (#62).** This window is the ONE place a device is named: `volumen.guardar()` also calls `fleet.guardar_nombre()` (`state/fleet.json`: the name «Dispositivos…» shows and the fleet note publishes), so Explorer and the list never call one device two things. «Dispositivos…» only reads it.
  - **`guardar_nombre()`, never `fleet.recordar()`.** `recordar()` writes `publicado` (what was last *uploaded*): using it would mark the new name as published with nothing sent, and `hace_falta_publicar()` would see no change. `guardar_nombre()` leaves `publicado` alone, so the old name there no longer matches `nombre()` and the next real pass publishes the note (`tests/test_fleet.py`, `tests/test_volumen.py` pin both halves). The save uploads nothing and needs no network; the window says the new name (and the icon, `volumen.mensaje_guardado()`) reaches «Dispositivos…» with the next sync.
  - **The icon travels the same way (#167):** `fleet.nota_de()` reads the key from `autorun.inf` when it publishes (`fleet.md`), so `volumen.guardar()` writes nothing extra for it; «Dispositivos…» shows the colour after the next real pass, and a `.ico` of one's own shows as the default mark.
  - **An empty name removes the drive's `label=` and leaves the fleet name alone**: `fleet.nombre()` treats a blank stored name as «the machine's name», so blanking it would silently rename the device after whatever computer it is plugged into.
  - **The fleet part goes last.** If the drive could not be written nothing about the device changes; if only `state/fleet.json` fails, `guardar()` raises a `VolumenError` saying the drive IS saved and which part is missing (saving again retries). Every save converges both names on the form's, also when only the icon changed.
  - **The agent reads the pair back**: a fleet name equal to the root's `label=` is one a person chose, even if it is also the name of a host the drive published from (`agent.md`, «The name shown for a drive»). So `label=` on `DEVICE_ROOT` must stay written only here, with the same text as the fleet name; the traveler's `label=` goes on the physical root, never there.
  - `Estado.dispositivo` (the fleet name) feeds `volumen.pista_nombre()`, the hint under the field. The fleet name has no limit of its own, so what fits `autorun.MAX_NOMBRE` always fits it; older, longer names are replaced only when the person types a new one.
- **The window paints first and reads the drive after** (`volumen.leer()` on a thread: it reads `autorun.inf` and, on Windows, walks the drive letters for the container's physical root). Until it lands the name, the colours, «Uno tuyo»/«Elegir…», «Ninguno» and «Guardar» are disabled; `Estado` is what «Guardar» uses, so it never acts on a read that has not happened. The read is launched before the first widget is built, so it is normally in by the time the pane is whole and the pane never shows its waiting line (`ui.md`).
- The five colours are `icons.CAMPOS` (brand field only; white and amber stay). Painting one takes ~2 s (256 px size), so the save runs in `tk.working()` and an existing file is never repainted.
- Seen on real Windows 11 (#63, 15/10/2026): Explorer does **not** read `autorun.inf` on a mounted VeraCrypt volume (above); a hand-set `Drives\<L>\DefaultIcon` showed an icon inside the hidden `.prdrive/` on one; with BitLocker the name is read but the padlock wins over the icon (not pursued); on a `subst` letter, `explorador.poner()`/`quitar()` against the real registry gave «Pendrive Ñ (S:)» with the icon and then left nothing, and `:olvidar_letra` removed only the subkey marked with its id.
- Unverified on real Windows (rows I1–I7 of `docs/superpowers/pruebas/2026-09-25-equipo-pendiente-en-real.md`): prdrive itself doing it on a real VeraCrypt volume; **`DefaultLabel` on a VeraCrypt volume** (seen only on `subst`); whether `SHChangeNotify` refreshes an Explorer window already open or F5 is needed; the unencrypted case (undiagnosed); a *change* of name or icon through `autorun.inf` (M1 saw a first write). The per-drawing file name is there so the icon cache cannot win.
