# The drive's name and icon (`common/autorun.py` + `ui/volumen.py` + `ui/tk_volumen.py`)

Formerly AGENTS.md «The drive's name and icon».

«Ajustes» → «Nombre e icono de la unidad…» sets what Windows Explorer shows for the drive via the root's `autorun.inf`: `label=` and `icon=` are still read on arrival though AutoRun has run nothing from removable media since Windows 7. No admin, any filesystem, accents allowed; the filesystem label is untouched. Seen on real hardware only for the traveler's file (M1 in the VeraCrypt results): it shows **after replugging**, and the window says so.

- **The file is edited, never rewritten.** `autorun.con()` replaces `label`/`icon` under `[autorun]` and keeps every other line; `autorun.sin()` drops only the keys its caller names. `traveler.write_autorun()` edits too: it keeps an existing label, a non-VeraCrypt icon and every foreign line; re-points a VeraCrypt icon at the executable the drive carries now (`vestibulo.traveler_ejecutables()`; `autorun.ICONOS_VERACRYPT` also recognises the old `VeraCrypt\VeraCrypt.exe`); and **removes** the `action=` / `shell\montar…` / `shell\desmontar…` it used to write (Windows ignores them on a removable drive (M2) and they pointed at an exe the portable lacks). UTF-16 + CRLF like VeraCrypt's own; `buscar()` matches the name case-insensitively. Nothing left → file deleted.
- **Which root**: always `DEVICE_ROOT`, the volume that holds the data. Unencrypted it is the drive plugged in; with BitLocker, the unlocked volume (the same one); with VeraCrypt, the **mounted** volume: Explorer reads its `autorun.inf` when the container is opened, as for any arriving volume. The container's physical root (the vestibule's, `vestibulo.raiz_fisica()`) is **never written**: it is the USB stick, and it keeps whatever name and icon it has (the traveler's, or one written there by an earlier prdrive). `Estado.fuera` carries it only so the window can say so and say the change shows when the drive is *opened* (`volumen.cuando_se_ve()`). The window prints the path it writes to.
- **Where the icon lives**: `Estado.carpeta`, always `.prdrive/` (`icon=.prdrive\icono-verde.ico`, from `APP_DIR.name`, not hard-coded), so the root holds only `autorun.inf`. A prefixed icon loose on a root (`.prdrive-icono-verde.ico`, `autorun.PREFIJO_RAIZ`) is no longer written but still recognised: `recoger()` collects one on the root it writes to, and `device.es_ruido()` counts it as noise on a physical root that still carries one (hashed names cannot sit in the `RUIDO` set). The VeraCrypt icon is offered only where the traveler is on the same root, so not on a mounted container.
- **The choice is read back from `icon=` itself**, no separate state: the icon file name carries the key (`icono-verde.ico`), a user's `.ico` a hash slice (`icono-propio-<8 hex>.ico`), and counts only where prdrive would put it (bare inside `.prdrive/`, or prefixed loose on the root). A new drawing is a new name because Explorer caches icons by path; `recoger()` then deletes our other icons, at the root too (this moves an old root icon into `.prdrive/` on the next save). An `icon=` prdrive did not write reads as `OTRO` and survives a name-only save.
- **The name is the device's name too (#62).** This window is the ONE place a device is named: `volumen.guardar()` also calls `fleet.guardar_nombre()` (`state/fleet.json`: the name «Dispositivos…» shows and the fleet note publishes), so Explorer and the list never call one device two things. «Dispositivos…» only reads it.
  - **`guardar_nombre()`, never `fleet.recordar()`.** `recordar()` writes `publicado` (what was last *uploaded*): using it would mark the new name as published with nothing sent, and `hace_falta_publicar()` would see no change. `guardar_nombre()` leaves `publicado` alone, so the old name there no longer matches `nombre()` and the next real pass publishes the note (`tests/test_fleet.py`, `tests/test_volumen.py` pin both halves). The save uploads nothing and needs no network; the window says the new name reaches «Dispositivos…» with the next sync.
  - **An empty name removes the drive's `label=` and leaves the fleet name alone**: `fleet.nombre()` treats a blank stored name as «the machine's name», so blanking it would silently rename the device after whatever computer it is plugged into.
  - **The fleet part goes last.** If the drive could not be written nothing about the device changes; if only `state/fleet.json` fails, `guardar()` raises a `VolumenError` saying the drive IS saved and which part is missing (saving again retries). Every save converges both names on the form's, also when only the icon changed.
  - `Estado.dispositivo` (the fleet name) feeds `volumen.pista_nombre()`, the hint under the field. The fleet name has no limit of its own, so what fits `autorun.MAX_NOMBRE` always fits it; older, longer names are replaced only when the person types a new one.
- The five colours are `icons.CAMPOS` (brand field only; white and amber stay). Painting one takes ~2 s (256 px size), so the save runs in `tk.working()` and an existing file is never repainted.
- Unverified on real Windows: an icon inside the hidden `.prdrive/`; Explorer reading `autorun.inf` on a mounted VeraCrypt volume (the earlier physical-root placement was seen to rename the stick, not the volume, which is why it moved); whether Explorer reads the file when a BitLocker drive is *unlocked* (locked, it cannot); a *change* of name or icon (M1 saw a first write). The per-drawing file name is there so the icon cache cannot win.
