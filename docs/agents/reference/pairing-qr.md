# Pairing a phone (`common/pairing.py` + `ui/qr.py` + `ui/tk_qr.py`)

Formerly AGENTS.md «Pairing a phone».

«Ajustes» → «Emparejar un móvil» (a pane; inside «Ajustes» the protection below covers the whole window while the code is shown) shows the device's connection as a QR so a phone can read it. Three pieces, none knowing the others' medium:

- **`ui/qr.py` is a full QR encoder**, written here for the same reason `ui/icons.py` draws its own icons: no dependencies. Byte mode only (the payload is UTF-8 with base64 inside; the other modes save nothing); everything else is complete: 40 versions, four ECC levels, block-interleaved Reed-Solomon, all eight masks and the penalty score that picks one. Constants cite **ISO/IEC 18004** the way `common/bisync.py` cites rclone: **preserve those citations.** Only two tables can't be derived (`_CORRECCION_POR_BLOQUE`, `_BLOQUES`); the rest is computed, and `tests/test_qr.py` pins the derivations against the published byte-mode capacities, which would catch a mistyped digit in either table.
- **`common/pairing.py` builds the payload and lives in `common/` on purpose**: `install/` does not travel to a provisioned device and this runs *on* one, with no network. Same reason `parse_rclone_conf()` moved here and `install/profile.py` re-exports it: **one reader of rclone.conf, not two**; `RUTAS_DERIVADAS` is shared likewise.
- **The payload format is `profile.dumps()`'s plus three keys** (the `prdrive` marker, `private_key_b64`, `known_hosts`). Those are surplus to `profile.loads()`, so the *same text* goes straight into it: no second parser, no translation layer. `tests/test_qr.py` does the whole round trip (device → payload → QR → decoded → `profile.loads()`) and keeps the formats from drifting. **All bare keys must precede `[options]`**: a stray line after the table header would put the private key inside the backend's options and from there into the phone's rclone.conf.
- **It shows a private key on screen and says so**, in an amber block. It is not a token and does not expire: whoever photographs the screen gets the remote. The window stores nothing and copies nothing to the clipboard.
- The window asks for correction **L**, not the module's default M: the medium is a screen (no creases, print or dirt) and capacity is what is scarce; an RSA-3072 key fits in *no* version at M. It fails with a sentence, not a stack trace, when even L is not enough.
- `icons.matriz()` rasterises the modules (pure black and white, integer module size, quiet zone added there) and does **not** cache: the caller holds the reference or Tk loses the image.

## The pane paints first, the code arrives later

Reading the device's connection and encoding it (`pairing.construir()`: `rclone.conf` and the private key from disk; `qr.codificar()`: Reed-Solomon, eight masks) is **not done on the Tk thread**. `tk_qr.construir()` paints the header, the amber notice, the hint, the footer and an empty card saying «Preparando el código…», and asks a thread for the code. This is a security-sensitive path, so what it must hold:

- **`tk_qr.preparar_codigo(raw_local) -> qr.Codigo`** is the thread's work (an indirection point: tests replace it) and goes through plain `segundo_plano.lanzar()` into the pane's own `panel.sondeo()`. **The payload text, which carries the private key, never leaves it**: it is not returned and not kept (the local is deleted in a `finally`); only the modules come back, which are what the screen shows anyway.
- **Never `lanzar_sin_repetir()`.** Its live-reads table (`_EN_VUELO`) would keep the `Encargo`, and with it the code, after the pane is gone, and would hand an older code to a later pane. `tests/test_tk_apartados_lectura.py` asserts the table is empty after the code has arrived.
- **On arrival (`llegada()`), in this order**: (1) in «Ajustes», the `<Destroy>` binding on the pane's frame that calls `tk.soltar_capturas()`; (2) `proteger_de_capturas(dlg)`; (3) `icons.matriz()` and its label; (4) the version line and the capture line under the amber block (row 2, from what (2) returned); (5) `panel.ajustar()`, because the card grew. The protection goes first so there is never an instant with the code on screen and the window unprotected, even when the window was already open (in «Ajustes» the label is created now, and Tk paints it at idle, after (2)). If `matriz()` cannot draw, the protection is lifted again (`soltar_capturas`) and the card says so: no code on screen, nothing to protect, and a window that vanishes from captures would not let the error be photographed either. If the read failed (`ConfigError`, `qr.QRError`, anything else), the card says why and nothing is protected.
- **A pane left before the code arrives creates nothing and protects nothing.** The `Sondeo` hangs off `panel.marco` and dies with it, so the callback never runs: no image, no protection, no binding. The pane must be **destroyed** when left, not hidden and kept: a paused `Sondeo` would deliver on `mostrado()`, and a kept pane would keep the image after its protection was lifted. «Ajustes» destroys it; if that ever changes, the QR pane must be excluded.
- **Standalone** (`open_dialog`), the window is shown before it is protected, with no code on it yet: there is nothing to capture until the code arrives. `tests/test_captura_pantalla.py` sets `segundo_plano.lanzar = en_el_acto` for its existing cases, so there the code is in before `mostrar()` and the protection still comes before it; the cases that matter for the new order use an `Encargo` that is released by hand (the code arriving late, leaving before it arrives, and «Ajustes» → «Configuración» → QR protecting twice and lifting once in between, with `IS_WIN` forced and `wm frame` made to differ from `winfo_id()`).

## Screen-capture protection on Windows (#59)

Keeps the window out of screen captures. It stops an accident (a shared screen, an OBS recording, a Snipping Tool shot ending in a chat), not an attacker: the amber block stays the real barrier.

`tk.proteger_de_capturas(window)` runs when the code **arrives**, before its image exists (see «The pane paints first, the code arrives later» below), and only when there is a code to show. It is `SetWindowDisplayAffinity` via ctypes: `WDA_EXCLUDEFROMCAPTURE` (0x11, Windows 10 2004+: absent from the capture) and, if refused, `WDA_MONITOR` (0x1: present as a black rectangle); neither → unprotected. It never raises and never stops the window opening; off Windows it does nothing.

- **It returns WHICH protection took, not a bool**: `CAPTURA_EXCLUIDA`, `CAPTURA_EN_NEGRO` or `CAPTURA_NINGUNA` (the `GetWindowDisplayAffinity` values; falsy only for the last, so `if proteger_de_capturas(w):` still reads «is it protected»). A bool cannot carry it because the line under the amber block must be true for each: «no aparece» is false for the black rectangle (`tk_qr.LINEA_CAPTURA`, one sentence per value).
  - **No protection on Windows says so** (`tk_qr.LINEA_SIN_PROTECCION`, «No se ha podido proteger esta ventana de las capturas de pantalla.», chosen by `tk_qr.linea_de_captura()` from `tk.IS_WIN`): whoever shares the screen trusting the protection must learn it did not take; a silent failure reads as success.
  - **Off Windows it stays silent**: silence promises nothing, and Linux has no equivalent (X11 has no API, Wayland decides in the portal) and must not hint otherwise. No code on screen → no line at all.
- **The HWND is `wm frame`, never `winfo_id()`, and the wrapper must exist first** (Tk 8.6.15, `win/tkWinWm.c`, `win/tkWinWindow.c`, `generic/tkFrame.c`). Tk wraps each toplevel in a wrapper window that `UpdateWrapper` creates the first time it is mapped, at idle (`MapFrame` → `TkWmMapWindow`); `withdraw()` does not create it, but the mapping does, hidden (`SW_HIDE`). Until then `wm frame` returns Tk's own window (the one `winfo_id()` gives, a parentless `WS_POPUP`), which accepts the affinity and loses it when Tk moves it into the wrapper: protected on paper, not in fact. So the function runs `update_idletasks()` first and protects nothing if `wm frame` still equals `winfo_id()`. The code now arrives after the window has been shown, so the wrapper already exists and the guard is the safety net, not the common path (it still matters when a test or a caller protects a window that was never mapped).
- **After it, nothing may restyle the window** (`resizable`, `transient`, `overrideredirect`, style `attributes`): `UpdateWrapper` destroys the wrapper and builds another, and the affinity belongs to the HWND. `modal()` and `mostrar()` do theirs before the code arrives; after it only `panel.ajustar()` runs (`Visor.crecer()` and `centrar()`: `geometry`, which does not rebuild the wrapper).
- **Not covered (the docstring says so)**: a photo with another phone; a privileged program reading the screen; Magnifier and accessibility tools; Remote Desktop (whoever connects sees it black). The window's line does not list them: the amber block already says a photo is enough.
- `tests/test_captura_pantalla.py` fakes the window (its wrapper appears at the first idle, like Tk's) and `_afinidad_de_pantalla`, and runs the real ctypes wrapper against a fake `ctypes.WinDLL`. What only Windows can say (`wm frame` with the window withdrawn, the captures themselves, Remote Desktop, ARM64, a Windows older than 2004) is in `docs/superpowers/pruebas/2026-10-02-captura-qr-pendiente-en-real.md` (C0 checks the HWND with a stdlib script).
