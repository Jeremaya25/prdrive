# Engine: config → command, bisync, logs

Files: `sync.py`, `common/model.py`, `common/bisync.py`, `common/config_file.py`.
Formerly AGENTS.md «Architecture», «bisync», «Logs and live progress», «Writing the TOML».
The safety invariants (missing local dir, `max-delete`, mirrors) stay in AGENTS.md. Their one narrow exception is the keychain's: a pass whose only deletions are conflict copies is repeated once without the `max-delete` brake (`sync.repetir_sin_freno()`, `llavero.md`).

## Process split

`sync.py` is the engine. `runsync.py` never imports it: it reads config via `common.model` and shells out to `model.SYNC_PY <pair>` per pair, so they share no in-process state.

## Parse once, at the boundary

`model.parse_config()` turns the TOML into frozen `Mode`/`Pair`/`Config`. Nothing downstream re-reads TOML keys, repeats `.get(key, default)` or threads `defaults` through signatures. New mode = one `Mode(...)` in `MODES`; an invalid one fails at parse time, so a typo stops `--list`/`--doctor`/runs alike.

Validation raises **`model.ConfigError`**, never `sys.exit`: the UI shares the model and exiting would close the window. CLI entry points catch it and exit with its message. `install.InstallError` exists for the same reason.

## Config → command

Flags merge last-wins inside `model._build_pair`: `BASE_FLAGS` < `Mode.flags` < `[defaults.flags]` < `[pair.flags]`. `Pair.flags` arrives ready; `build_command()` adds only what depends on *this* run.

`model.flags_to_args()`: `key = value` → `--key value` (`true` → bare flag, `false`/`None` → dropped, list → repeated, `_` → `-`). It lives in `model.py` so the UI can show a flag's effect without importing the engine.

**A new rclone flag = edit the TOML, never code.** The script owns `--config`, `--log-file`, `--dry-run`, `--workdir`, `--resync`, and with it `--resync-mode`: rclone treats that flag as `--resync` (`setResyncDefaults()`, `cmd/bisync/resync.go`), so `build_command()` drops it from a pass that is not a resync and it only says which side wins when `sync.py` resyncs (the keychain's `newer` was turning every pass into a resync until the cloud run of 2026-10-05); `extra_flags` is the raw-string escape hatch. `RunContext` holds what is constant across the pairs of one invocation.

**`model.comprobar_seguridad(crudo)` is the gate for what reaches rclone's argv.** The config travels with the device and is hand-edited, so it refuses, with a `ConfigError`:

- `model.problema_flag()`: the script's own flags (`FLAGS_RESERVADOS`, so `resync = true` can no longer force `--resync` on every pass), any flag that makes rclone run a program on this computer (a normalised name ending in `-command` or `-ssh`, `metadata-mapper`, `rc` and `rc-*`: `--password-command`, `--sftp-ssh`, `--webdav-bearer-token-command`, the `rc` server) and any flag that writes or truncates an arbitrary host file (`FLAGS_ESCRIBEN`: `--cpuprofile`, `--memprofile`, which rclone `os.Create`s in `cmd/cmd.go`). A key with `=` (`"sftp-ssh=sh -c id" = true`) reaches rclone as one `--key` argument, so it is judged by what precedes the `=`. The suffix rule also blocks `--sftp-*-command` as flags; as remote options they still work in `rclone.conf`. Nothing is added to `FLAGS_RESERVADOS` for convenience: a refusal at load is a `ui.fatal` that keeps the window closed until the TOML is edited by hand, so only what is a security problem is refused. That is a deliberate boundary, not a claim of completeness: the gate refuses the script's reserved flags, flags that run a program, flags that write arbitrary host files, unsafe remote names and a `local` outside the root. What it does not cover (backend-option redirects such as `--sftp-host`, `--*-url`, `--*-endpoint`; `--temp-dir`/`--cache-dir`; the `--*-from` filter files) is listed under “Not covered” in `agent.md`.
- `model.problema_extra()`: every `--name[=value]` token of `extra_flags`, by its name and with the same rules (`--config /tmp/x` would override the script's; `--Resync` is `resync`). A single-dash short flag passes, and so does a bare value.
- `model.problema_valor_flag()`: the **values** of `[defaults.flags]`/`[pair.flags]` go through `problema_extra()` too (a scalar is one token, a list one per item). `flags_to_args()` emits `--key value` and a boolean flag does not consume the next argument, so `checksum = "--sftp-ssh=sh -c id"` would reach rclone as `--checksum --sftp-ssh=sh -c id`. Values that do not start with `--` (`8M`, `25`, `newer`, `-1`) are untouched.
- `model.problema_local(local, equipo)`: `local` is a folder INSIDE the device, relative to its root. A `local` that is present but not a text (`local = ["a/../../etc"]`, which `_build_pair()` would read with `str()`) is refused by `comprobar_seguridad()` before this. Refused, on the raw text with `\` read as `/`: a `..` segment, a first segment with a drive prefix (`C:`, `d:x`), a segment made only of dots and spaces other than a lone `.` (`...`, `. .`, `.. `), a `:` in any segment (`docs:stream`, `.prdrive::$INDEX_ALLOCATION`: on Windows `name:stream` is an NTFS data stream of `name`), and a first segment equal (case-insensitively, after `rstrip(". ")`: Win32 path normalisation turns `.prdrive.` and `.prdrive ` into `.prdrive`) to the program's folder (`APP_DIR.name`, `.prdrive` on a device: the program, with the key; `carpeta_programa=` overrides it for whoever reads another root's config) or to `LLAVERO_LOCAL` (`.keychain`: the keychain has its own pair). Only the first segment counts for those two names: `sync-data/.keychain` is an ordinary folder. What no text gives away (8.3 short names, junctions, symlinks into the program folder) is stopped at run time by `model.problema_contencion()`. A leading `/` is tolerated on drives (`normalizar_local()` strips it and devices in use may have it). On a host root (`equipo`, passed by `parse_config(equipo=)` and by `agente.leer_servicio()` from `es_equipo()`; the agent also passes `carpeta_programa=APP_SUBDIR`, because there `APP_DIR` is the agent's own folder, not the drive's `.prdrive`) `problema_local_equipo()` goes first and keeps its own words (`host-root.md`). Without it, a drive's `local = "../../fuera"` makes the `combine` upstream `..=<parent>` and `C:/…` leaves the device on Windows. It lives in `comprobar_seguridad()` and not in `_build_pair`, so the agent applies it too.
- `model.problema_remote()` (`NOMBRE_REMOTE`): a `remote` with `,` `:` `=` or quotes, or a leading `-`, is an rclone connection string (`nas,ssh='sh -c id'` is an `sftp` remote with its own command), not the name of a remote of `rclone.conf`. A name of exactly one ASCII letter (`C`, `n`) is refused too: rclone reads `C:path` as the Windows drive C (`fs/fspath/path.go`), so the remote would resolve to a local folder; the message says to rename it with two characters or more. It covers the pair's `remote` and, in `[defaults]`, both `remote` and `catalog_remote` (checked as soon as the key is present, **even when empty and even when every pair has its own `remote`**: an empty default would leave a pair with no `remote` on `:remote_path`, where a crafted `remote_path` is a connection string): `carpeta_del_catalogo()` takes them as they are for the keychain pair and `catalog.endpoint()` for the `rclone cat` of the catalogue.
- `include`/`exclude` (`_comprobar_patrones()`): an entry with `\n` or `\r` is refused, in a pair and in `[defaults]`. `bisync.filters_content()` writes one rule per line, so `exclude = ["x\n!\n+ **"]` would add a lone `!` (rclone resets the rule list, dropping `REGLA_SIN_PROGRAMA`, `REGLA_SIN_LLAVERO` and `- .prversions/**`) and a `+ **`.

`comprobar_seguridad()` works on the **raw** dict (`tomllib`'s output) and tolerates any shape (non-table values, non-text names, no `[[pair]]`) and decides nothing else: an unknown mode or key is not its business. It covers `[defaults]` (`remote`, `catalog_remote` whenever the key is present, `flags`, `extra_flags`, `include`/`exclude`; errors prefixed `[defaults]`) and each named pair (`remote`, `flags`, `extra_flags`, `include`/`exclude`, `local`; prefixed `[<pair>]`). `extra_flags` is checked as `_as_tuple()` will emit it (an inline table gives its keys; a value that is not iterable is a `ConfigError`). `_build_pair` also checks the `remote` that comes out of the fallback chain (`[<pair>]`), so no path skips it. It is the single place for these raw checks: `parse_config()` calls it first, and `agente.leer_servicio()` calls it on the raw TOML it reads (`agent.md`), because a drive whose own `sync.py` predates the rule checks nothing. Every message names the layer, the key or the argument, and says what to do (`QUITALO`, «Quítalo del config.»): a refused config is a `ui.fatal` and is fixed by hand. The keychain pair is built by code and not checked: it keeps `resync-mode`. `ui/flags_editor` re-exports `RESERVED` and `normalize` and calls the same functions (`problema_flag`, `problema_valor_flag`, `problema_extra`), so the dialog says it while typing; `tests/test_parseo_seguro.py`.

**Runtime containment: `model.problema_contencion(pair)`.** No text check sees where a `local` really lands: an 8.3 short name, a junction or a symlink can take an innocent-looking `local` into `.prdrive/` (the key), where a `down-mirror` would delete it. `run_pair()` therefore asks, before anything else (also for non-bisync pairs, which have no preflight), whether the resolved `local_abs` or `top_level_abs` IS `model.APP_DIR.resolve()` or is inside it, and if so aborts that pair with rc 2 and a message, recorded like the other aborts (`record_result()`). A root pair (`local = "."`) contains the program folder but is not inside it, so it passes (it carries `REGLA_SIN_PROGRAMA`). There is deliberately **no** general «outside the device» check: a host root may symlink out on purpose (`host-root.md`). `tests/test_parseo_seguro.py` (POSIX; prints `(saltado)` where symlinks cannot be made).

## bisync (`common/bisync.py`)

The one place that imitates rclone's behaviour; each section cites the rclone source it mirrors. **Preserve the citations.**

- **Session prefix.** `canonical_path`/`session_name`/`expected_prefix` replicate `cmd/bisync/bilib/canonical.go`, so the listing name is known **before** running. Used by `pair_editor` (does this baseline still belong to this pair?), `revision` (the «prefijo» finding, `--doctor`) and the keychain (`llavero.listado_local()`). `FsPath` writes `name:` + the backend's `Root()`, which is the path as given except for an rclone remote of `type = local` in the device's `rclone.conf` (`bisync.tipos_de_remote()`, read with `pairing.parse_rclone_conf()`): its `Root()` is `cleanRootPath()` (`backend/local/local.go`), replicated by `raiz_local()` and checked against rclone v1.75.1. On Linux, the cleaned path (`a//b`, `a/./b` → `a/b`; a `.` or `..` segment encoded as `．`/`．．`). On Windows (`bisync.IS_WIN`), absolute from `APP_DIR` (rclone's cwd) and long-path: `D:\x` → `//?/D:/x`, `\\srv\x` → `//?/UNC/srv/x`, unless `nounc = true`. Without it, a Windows pair with a `local` remote expected `nas_D__…` where rclone wrote `nas_____D__…`: passes ran (`pair_state()` globs), but the keychain never found its listing and `revision` would call the baseline someone else's (found by `llavero-real.yml`). Other wrapping backends (`alias`) are not replicated. `tests/_harness.sandbox()` moves `RCLONE_CONF` too, so no test reads the checkout's.
- **`device_remote`, on by default** (`DEFAULT_DEVICE_REMOTE = "disp"`; `deploy.device_config()` `setdefault`s it into each new device's `[defaults]`). It makes the device side a `combine` remote via `RCLONE_CONFIG_<NAME>_TYPE/_UPSTREAMS` (`Config.pen_environment()`, built from **all** pairs), so the prefix is machine-independent; `alias` does not work. It belongs to the **device's** defaults: in the catalogue it would move every installed device's prefix at once.
- **Quoting `upstreams`.** rclone parses it as an `fs.SpaceSepList` (`fs/types.go`): space-separated CSV, a field quoted only if it **starts** with a quote. So the quotes wrap the whole `name=path`, never just the path: `.="F:\"` gives `bare " in non-quoted-field` and takes **every** pair of the device down. They exist for a drive root's trailing backslash and for spaces. `model._upstream()` is the only builder.
- **The device root needs a named upstream.** rclone cleans the path first, so `local = "."` becomes upstream `""` and fails with `combine for remote "": directory not found`. `model.RAIZ_UPSTREAM` (`"raiz"`) names it, hence `top_level_dir` (the name) and `top_level_abs` (the folder). The name is part of the prefix: changing it invalidates those baselines.
- **No listing rename** (`normalize_prefix`, `rename_prefix`, `heal_listings` were deleted with `device_remote`). Renaming a listing set tells bisync that a listing of the *previous* destination describes the *new* one, and the benign case is indistinguishable from the malignant. Legacy devices are fixed by hand; no migration code. `tests/test_bisync_prefijo.py` asserts the absence and guards both halves of `device_remote`.
- **Filters.** bisync only (`Pair.wants_filters_file`): `filters_file_for()` writes `filters/<pair>.txt` and passes `--filters-file`; `--include`/`--exclude` are then **not** also emitted (duplicate rules break change detection). Code-owned rules (`Pair.reglas`: the keychain's; and on every root pair, `local = "."`, `REGLA_SIN_PROGRAMA` (`- /<APP_DIR.name>/**`) followed by `REGLA_SIN_LLAVERO` when `[keychain]` exists, `llavero.md`) go right after `- .prversions/**`, before the TOML's; outside bisync they become `--include`/`--exclude`. bisync rewrites the md5 beside the file only on `--resync`, so `filters_state()` compares the hash itself and reports "needs resync".
  - **A root pair never carries the program's folder.** Without `REGLA_SIN_PROGRAMA` a `local = "."` pair uploaded `.prdrive/` (the SSH key in `keys/`, `rclone.conf`) and a root `down-mirror` would delete it. `parse_config()` builds the root rules once and gives them to every root pair; the user's TOML cannot remove them, and a `+` of the pair comes after them. The rule is the program folder's name, so a device's `.prdrive/` and a dev checkout's folder each exclude their own. **Outside bisync it is an `--exclude`, and rclone puts every `--include` before every `--exclude`** (`fs/filter/filter.go`, `NewFilter`; see `sync.filter_args()`): a copy/sync root pair whose own `include` matches the program folder still carries it, the same gap `llavero.md` words for the keychain rule. In bisync the rule precedes the pair's `+` rules, so there is no such gap.
  - **A root bisync pair that predates the rule needs one `--resync`**: its filters file changes, so `filters_state()` says `changed`, the window offers the resync, and the service and the agent skip the pair until then (the agent says so once and the tray keeps listing it as «necesita --resync»: `Agente.saltadas`, `agent.md`, `tray.md`). Non-bisync root pairs need nothing. **Nothing deletes a copy that already reached the remote**: `bisync.programa_en_listado()` looks for the folder in the baseline's `path2` listing (best effort: missing or unreadable means no), and `revision.carpeta_programa_en_remoto(pair)` is the ONE decision built on it (`es_raiz` and listed → the remote folder, built from `remote_name` and `remote_path` as they are: `""` is `nas:.prdrive/`, `"/"` is `nas:/.prdrive/`, `"R/p/"` is `nas:R/p/.prdrive/`, since relative and absolute differ in SFTP). It is said **before** the resync, on purpose: afterwards the new listing no longer shows the folder, and the resync is approved in three places that all ask `carpeta_programa_en_remoto()` and print `revision.aviso_carpeta_programa()`: the pair's `resync` finding (`dato`, detail; `repair.aviso_resync()` in «Reparación»), the main window's prompt (`ui.manual_args()` → `ui.carpetas_del_programa()` → `tk.preguntar_resync()`) and `sync.resolve_resync_approval()` (console, also with `--yes`).
- **State.** One workdir per pair, `Pair.workdir` → `state/<pair>/` (`migrate_legacy_state()` moves the old flat layout). `pair_state()` → `PairState(status, detail, prefix)`, `fresh|ok|broken`, read from the real `.lst` files. `resync_reasons(pair)` = why a pair needs `--resync` (`[]` for non-bisync; the mode guard is inside). `last_run(pair)` = mtime of the newest listing = the last good pass (None for non-bisync).
  - A `.lst-err` is the baseline rclone sets aside when a pass aborts (`cmd/bisync/operations.go`, `markFailed()` in `lockfile.go`; with `--recover` the next pass goes back to `.lst-old` and leaves them). The state line says what they are and that they may be deleted by hand; **nothing deletes them**: bisync's workdir is not ours to clean.
- **Resync approval.** `resolve_resync_approval()` asks **once** for all pairs before anything runs; `ask_yes_no()` returns the default when stdin is not a tty, so non-interactive runs skip those pairs (`SKIPPED = -1`) rather than resync unattended.
  - **The one exception is the keychain pair** (`pair.llavero`): `_bisync_preflight()` resyncs it whenever `resync_reasons()` says so, unasked, and it is left out of the question, of `ui.pair_status_notes()` and of `revision`'s `resync` finding. Its `resync-mode = newer` keeps the newer base and the backup dir catches the other side's (a `--resync` honours it too), so nothing is lost; skipping it would leave it silently unsynced, since a skipped pass exits 0. The «local path missing with a baseline» abort still runs first.

## Logs and live progress

rclone writes to a temp file; `dispose_log()` keeps it in `logs/` only if the run failed (or `--keep-logs` / `keep_logs = true`), to spare device write cycles. On failure the tail is printed and `KNOWN_ERRORS` maps rclone messages to an explanation: add new cases there.

Device vanished mid-pass (#36): `keep_log()` leaves the log in the temp dir, says so in one `AVISO` line (any half-copy in `logs/` removed) and returns that path, so tail and explanation still come out. `run_all()` turns an `OSError` from the pairs after it into a `FALLÓ` line, never a traceback.

- `--log-file` only catches what rclone logs **after** installing the log, so `execute()` captures rclone's `stdout`+`stderr` (captured, not inherited: with no console behind it, inherited output is lost) and `append_output()` appends it under `DIRECT_OUTPUT_HEADER`.
- `strip_usage()` drops the 12 KB help dump rclone prints after a bad flag: it mentions `--max-delete` and `lock file`, so `explain_failure()` matched a `KNOWN_ERRORS` needle inside rclone's own docs. **A false diagnosis is worse than none.** The two flag entries in `KNOWN_ERRORS` go **last**.
- A needle matches rclone's **error**, never a routine line that also appears in passes that fail for another reason: bisync logs `lock file renewed` on every pass (hence `prior lock file found`), and sftp logs `No host key validation is being performed. Set known_hosts_file …` on every pass to a remote without one (hence `couldn't parse known_hosts_file`, `NewFs` in `backend/sftp/sftp.go`).
- **Live progress.** `BASE_FLAGS` has `--stats 2s --stats-one-line` (base layer, so a pair can override it); `execute()` runs rclone inside `seguir_progreso(logfile)`, a thread tailing the temp log: the **only** channel, no rc API or ports. Strictly best-effort: an unmatched line gives no progress and the thread swallows *any* exception.
  - The file is closed before `execute()` returns (Windows cannot delete or move an open file); `main()` line-buffers stdout (behind the window it is a pipe); `print_log_tail()` drops stats lines.
  - The regex mirrors `StatsInfo.String()` (`fs/accounting/stats.go`) and requires the ETA, so a line cut mid-write never yields a half number.

## Writing the TOML (`common/config_file.py`)

`tomllib` only reads and the project has no deps, so the serializer is hand-rolled: scalars, string arrays and one nested `flags` table. Preserve:

- `[pair.flags]` binds to the **last** `[[pair]]` written, so it is emitted right after its pair.
- `dumps_checked()` re-parses its output and refuses to write if the dict does not reproduce. `save()` and `catalog.push()` both go through it.
- **A table it does not know** (not in `TABLAS_CONOCIDAS`, e.g. a newer version's `[keychain]`) is written as is at the end. `model.parse_config()` ignores it on read, and dropping it on write would make `dumps_checked()` refuse the whole file, so a catalogue carrying it could not be edited. A subtable inside it is still refused by that check.
- Work on the **raw dict**, never `model.Config` (its `Pair`s have `[defaults]` merged). `save(head=None)` keeps the target's header.
