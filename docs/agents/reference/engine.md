# Engine: config → command, bisync, logs

Files: `sync.py`, `common/model.py`, `common/orden.py`, `common/bisync.py`, `common/config_file.py`.
Formerly AGENTS.md «Architecture», «bisync», «Logs and live progress», «Writing the TOML».
The safety invariants (missing local dir, `max-delete`, mirrors) stay in AGENTS.md. Their narrow exceptions are the keychain's, a pass whose only deletions are conflict copies, which is repeated once without the `max-delete` brake, and a pass stopped by «all files were changed», repeated once with `--force` only after a `--dry-run` of that repeat shows it deletes nothing (both `sync.repetir_sin_freno()`, one repeat per pass in total, `llavero.md`; named in `AGENTS.md`, «Safety invariants»), and a pass a person forces with `--force` (below, `repair.md`).

## Process split

`sync.py` is the engine. `runsync.py` never imports it: it reads config via `common.model` and shells out to `model.SYNC_PY <pair>` per pair, so they share no in-process state.

## Parse once, at the boundary

`model.parse_config()` turns the TOML into frozen `Mode`/`Pair`/`Config`. Nothing downstream re-reads TOML keys, repeats `.get(key, default)` or threads `defaults` through signatures. New mode = one `Mode(...)` in `MODES`; an invalid one fails at parse time, so a typo stops `--list`/`--doctor`/runs alike.

Validation raises **`model.ConfigError`**, never `sys.exit`: the UI shares the model and exiting would close the window. CLI entry points catch it and exit with its message. `install.InstallError` exists for the same reason.

## Config → command

Flags merge last-wins in **one** function, `model.flags_efectivos(mode, defaults_flags, own)`: `BASE_FLAGS` < `Mode.flags` < `[defaults.flags]` < `[pair.flags]`, one `FlagEfectivo(nombre, valor, origen)` per key with the layer that won (`ORIGEN_BASE`/`_MODO`/`_DEFAULTS`/`_PAREJA`). `_build_pair` takes `Pair.flags` and `Pair.origen_flags` (key → layer) from it and the flags editor takes its table from it (`catalogue.md`), so what the window shows and what `sync.py` reads cannot be two merges. It merges by the key **as written**: `max_delete` in a pair and `max-delete` in the mode are two keys and rclone receives both (the last wins), exactly as before the function existed; collapsing them by normalised name is the editor's job, not the cascade's, because it would change what rclone receives. `Pair.flags` arrives ready; `build_command()` adds only what depends on *this* run.

**The flags guide reads these tables** (`catalogue.md`, «The flags guide»): what each flag is (fixed by the script, rejected by the config, given a value by prdrive, or free) and its prdrive value come from `FLAGS_RESERVADOS`, `problema_flag()`, `BASE_FLAGS` and each `Mode.flags`. Changing any of them changes `docs/guia/flags-de-rclone.md`: **run `python generar_guia_flags.py`** (`tests/test_flags_guia.py` fails until you do), and give a flag prdrive starts to set an `Entrada` in `ui/flags_catalogo.py`.

`model.flags_to_args()`: `key = value` → `--key value` (`true` → bare flag, `false`/`None` → dropped, list → repeated, `_` → `-`). It lives in `model.py` so the UI can show a flag's effect without importing the engine.

**The command is built in one place: `common/orden.py`.** `sync.build_command()` only creates the temp log and calls `orden.orden_rclone(pair, binario=, filtros=, config=, logfile=, simulacro=, resync=, sello=)`, and the flags editor's command preview calls `orden.tramos()` with the same arguments (placeholders where only a run knows: `flags_editor.LOG_PREVIO`, `SELLO_PREVIO`; `bisync.ruta_filtros(pair)` is the filters path without writing it). `tramos()` is the command in order as `Tramo(args, origen, nombre)`: the verb and both endpoints, the filtering (`tramos_de_filtrado()`; `filter_args()` is its flat form), every flag (`flags_de_la_pasada()`: the pair's merged flags plus what the script adds per run, `--config`, `--log-file`, `--dry-run`, `--workdir`, `--resync`, the versioning five), then `extra_flags`. What the script adds is `ORIGEN_PRDRIVE`, the code's filter rules too (`Pair.reglas`), the pair's own patterns `ORIGEN_PATRONES`, the extras `ORIGEN_EXTRA`; a `conflict-loser` the pair set stays the pair's however it is spelled (`conflict_loser` too: the versions default is added only when no key normalises to `conflict-loser`, or rclone would get both and keep the last, prdrive's; one in `extra_flags` goes after every flag, so it wins by position and the default needs no special case). A flag turned off (`false`) produces no tramo. `tests/test_flags_efectivos.py` pins `build_command()` argument for argument on every mode, versions, a root pair, a dry run, a `--resync` and each spelling of `resync-mode` and `conflict-loser`, so the split can never move one; `tests/test_flags_editor.py` compares the preview against `sync.build_command()` for the same pairs.

**A new rclone flag = edit the TOML, never code.** The script owns `--config`, `--log-file`, `--dry-run`, `--workdir`, `--resync`, and with it `--resync-mode`: rclone treats that flag as `--resync` (`setResyncDefaults()`, `cmd/bisync/resync.go`), so `build_command()` drops it from a bisync pass that is not a resync **however it is written** and it only says which side wins when `sync.py` resyncs (the keychain's `newer` was turning every pass into a resync until the cloud run of 2026-10-05). The cascade keeps keys as written and `flags_to_args()` turns `_` into `-` at the end, so `resync_mode` in `[pair.flags]`/`[defaults.flags]` reaches rclone as `--resync-mode` just the same: `flags_de_la_pasada()` drops every key that `model.normalizar_flag()` reads as `resync-mode` (`orden._es_flag()`), and `tramos()` removes `--resync-mode V` / `--resync-mode=V` from `extra_flags` (`orden._sin_flag()`). A config that carries one is **not refused** (`problema_flag()`/`problema_extra()` accept it, and refusing a key would stop a config that loads today): the pass just ignores it, and a `--resync` still gets it; `extra_flags` is the raw-string escape hatch. `RunContext` holds what is constant across the pairs of one invocation.

**`--force` is the script's, for ONE pass** (#94). `sync.py NAME… --force` sets `RunContext.force` and `orden.flags_de_la_pasada(forzar=True)` adds what skips that mode's delete brake (`frenos.tiene_freno()`): `--force` for bisync (its `--max-delete`, a percentage, stays on the command and `--force` skips it: `cmd/bisync/operations.go`, checked with rclone v1.75.2), `--max-delete -1` **instead of** a mirror's count (`fs/accounting/stats.go`, `DeleteFile()`). rclone keeps the LAST `--max-delete` it gets, and the cascade keeps keys as written (`max_delete` is a second key, emitted after the mode's `max-delete`) while `extra_flags` go after every flag, so a forced mirror drops every `max-delete` key of the cascade, however spelled, and the `--max-delete N` / `--max-delete=N` of `extra_flags` (`orden._sin_flag(extra, "max-delete")`); `--max-delete-size` is another flag and stays (a forced pass can still stop at that brake), and nothing for a `copy`, which has no brake (`sync.py` says so and runs the normal pass), or for a pass that is a `--resync` (it never checks the brake, and that includes the one `_bisync_preflight()` decides alone for an empty reference, #113). `tramos(forzar=)` takes it too, so the flags editor's preview can show who puts it (`ORIGEN_PRDRIVE`). It needs **named pairs** (without names it would skip every pair's brake, which is what `runsync.py --daemon --force` would amount to) and does not combine with `--resync`: both are `parse_args()` errors, exit 2. **Never the keychain's, not by a person**: `frenos.se_puede_forzar()` (a brake and not the `llavero` pair) is the one rule for the pair, and the code's own single repeat of a keychain pass stopped by «all files were changed» (#115) is not a person forcing it: it puts `force` in the flags of a derived `Pair`, never in `RunContext.force`, so nothing below changes (`llavero.md`, «When rclone's brake stops a pass»), and `sync.py keychain --force` is refused in `main()` (`Config.select()` does pick it by name), the command builder ignores `forzar` for it, and `explain_failure(lpath, pair)` gives the keychain's own advice (`frenos.EXPLICACION_LLAVERO`: «Combinar») instead of the «fuerza UNA pasada» of the other brakes. A dry run with it (`--dry-run --force`) prints the files it would delete (`decir_lo_que_borraria()`, `repair.md`), but only when the pass really skips the brake. That is ONE rule, `orden.pasada_forzada(pair, forzar, resync)` (`forzar and frenos.se_puede_forzar(pair) and not resync`), shared by `flags_de_la_pasada()`, `_salta_el_tope()` and `sync._pasar_pareja()`, so the command, the announcement and the simulation report cannot disagree. Its `PASADA FORZADA` line tells the output window which brake is skipped, and it is printed only once the pass is known: after `_bisync_preflight()` and every abort (contention, a missing local folder, the keychain's refusals) and right before `build_command()`, so a pass that aborts or is skipped never claims to be forced. If `--force` was asked for and the pass turns out to be a `--resync` (requested and approved, changed filters, an empty reference, no baseline), the line is «--force no se aplica: esta pasada es un --resync, que no pasa por el freno», the command carries no `--force` and a `--dry-run` of it prints no «Simulación forzada». Nothing is stored, so the next pass brakes again.
- **Never from the TOML**: `force` is in `FLAGS_RESERVADOS`, so `[defaults.flags]`, `[pair.flags]`, `extra_flags` and a flag value all refuse it (and the editor, which re-exports the table). It is a `ConfigError` for any device whose config already had `force = true`, hand-edited or written by 0.7.4's flags editor (which took it without a warning): it asks the owner to remove it. With the config refused no window opens, so neither does «Reparación»: the `FLAGS_RESERVADOS["force"]` text says first what to remove and from which file (`.prdrive/sync_config.toml`, or the catalogue's `remote.toml`) and only then that, once removed, forcing is «Forzar sincronización…» or `sync.py PAIR --force`; and the fatal messages of `ui_flow`, `--auto` and `--llavero` end with `model.CONFIG_FILE` (`runsync.config_no_valido()`), as the agent's «config rechazado» notice does with the root's `sync_config.toml` (`agente.leer_config()`). A reserved key is refused whatever its value (`force = false` too). `max-delete = -1` **stays valid**, deliberately. In a mirror it is rclone's own «no limit» (`DeleteFile()` only counts when `MaxDelete >= 0`); in bisync it is **not** off: `applyContext()` (`cmd/bisync/cmd.go`) only honours a value `>= 0` and otherwise falls back to bisync's default, 50 %. Either way it is a permanent choice of whoever writes it (like `max-delete = 1000000`, which refusing only `-1` would not stop), and refusing it would break the config of a device that already carries it. The flags editor treats `max-delete` as the pair's brake and warns when it is removed or raised, but **not when it becomes `-1`** (a known gap, outside this change).
- **Who passes it**: the window's «Forzar sincronización…» after a confirmation (`repair.md`), or a person on a command line. The service (`run_pair_quiet()`), `--auto --once`, the agent and the main window never do (`tests/test_forzar_desatendido.py`).

**`modify-window = "2s"` is a base flag (`model.BASE_FLAGS`, `VENTANA_HORA`), for every pair and every mode (#114).** exFAT and FAT32 on Windows store the mtime in 2 s steps **rounded up**, also the one a program sets, and rclone measures the local side's precision with a probe file in the *host's* temp folder (`readPrecision()`, `backend/local/local.go`: `os.CreateTemp("", …)`, NTFS), not on the drive. So what came down from the remote read as changed on the next pass («File changed: time (newer)», then «Updated modification time in destination»: a pass that moves, a re-upload with a remote that has no sums, a spurious conflict if the remote changed in between). `fs.GetModifyWindow()` (`fs/fs.go`) takes the larger of this flag and each backend's precision, and `timeDiffers()` (`cmd/bisync/compare.go`) calls two times equal when they differ by **less than** the window, either way. Checked against rclone v1.75.2: bisync uses it where it compares times (`findDeltas()`, `deltas.go`: the same side across passes, the issue's case; the equal-content «changed in both paths» check; the listing validation, `listing.go`), and `copy`/`sync` use it in `operations.equal()`, so every mode gains. A pair changes it like any flag (`[pair.flags]`, `[defaults.flags]`).
  - **It cannot force a `--resync`.** It is in neither `bisync.expected_prefix()` (endpoints only) nor `filters_content()`/`filters_state()` (patterns only), and rclone's listings carry no flags (`ListingHeader` is just a date). `tests/test_ventana_hora.py` builds a baseline and a filters md5 with the old flags (no `modify-window`) and checks that the new ones read them as the same pair's, with no `resync_reasons()`; the cloud test F3 (`tests/maquina/f03_mtime_windows.py`, `f03_mtime_linux.py`, real NTFS/exFAT/FAT32/ext4 volumes with the pinned rclone; results in `docs/superpowers/pruebas/2026-10-15-ventana-hora-resultados.md`) also makes the baseline without the flag and runs the next passes with it.
  - **The cost.** On NTFS and ext4 it only drops a precision nobody needs, except that an edit of the same size made less than 2 s after the previous one may not be seen. And **`conflict-resolve = newer` does not use it** to pick the winner (`resolveNewerOlder()`, `cmd/bisync/resolve.go`, compares to the nanosecond): see the known limit in `conflicts-versions.md`.
  - `llavero.pendiente()` tolerates the same window (`llavero.TOLERANCIA_HORA`, `llavero.md`).

**The rclone it runs.** `model.rclone_binary()` finds the device's rclone (or the one the agent passes) and `model.ejecutable()` makes it runnable. On Windows, or when it already has the exec bit, that is the path itself. On POSIX a non-executable one (exFAT has no exec bit) is copied to `<XDG_CACHE_HOME or ~/.cache>/prdrive/rclone-<size>-<mtime_ns>`, never to a fixed name in a shared directory: the directory is `0o700` and the user's (someone else's, a symlink or a file raises `OSError`), the copy is written through a `.rclone-` temp in it and `os.replace`d, so a link planted at its name is replaced and never followed, and a copy already there (a regular file of that size, `lstat`) is reused, and its mtime is refreshed once it is over 12 h old (`RENOVAR_COPIA_RCLONE`) so a copy still in use never looks abandoned. After a new copy, other `rclone-*` / `.rclone-*` files untouched for a day (`COPIAS_RCLONE_VIEJAS`) are swept, best effort: the agent serves roots that may carry different rclone builds, and sweeping every other copy would make two roots take each other's away. `tests/test_rclone_portable.py` (POSIX only).

**`model.comprobar_seguridad(crudo)` is the gate for what reaches rclone's argv.** The config travels with the device and is hand-edited, so it refuses, with a `ConfigError`:

- `model.problema_flag()`: the script's own flags (`FLAGS_RESERVADOS`, so `resync = true` can no longer force `--resync` on every pass), any flag that makes rclone run a program on this computer (a normalised name ending in `-command` or `-ssh`, `metadata-mapper`, `rc` and `rc-*`: `--password-command`, `--sftp-ssh`, `--webdav-bearer-token-command`, the `rc` server) and any flag that writes or truncates an arbitrary host file (`FLAGS_ESCRIBEN`: `--cpuprofile`, `--memprofile`, which rclone `os.Create`s in `cmd/cmd.go`). A key with `=` (`"sftp-ssh=sh -c id" = true`) reaches rclone as one `--key` argument, so it is judged by what precedes the `=`. The suffix rule also blocks `--sftp-*-command` as flags; as remote options they still work in `rclone.conf`. Nothing is added to `FLAGS_RESERVADOS` for convenience: a refusal at load is a `ui.fatal` that keeps the window closed until the TOML is edited by hand, so only what is a security problem is refused (`force` is there for that: from the config it would skip the delete brake of every pass for good). That is a deliberate boundary, not a claim of completeness: the gate refuses the script's reserved flags, flags that run a program, flags that write arbitrary host files, unsafe remote names and a `local` outside the root. What it does not cover (backend-option redirects such as `--sftp-host`, `--*-url`, `--*-endpoint`; `--temp-dir`/`--cache-dir`; the `--*-from` filter files) is listed under “Not covered” in `agent.md`.
- `model.problema_extra()`: the tokens of `extra_flags`, **read the way rclone reads them** (pflag). A `--name[=value]` token is judged by its name with the same rules (`--config /tmp/x` would override the script's; `--Resync` is `resync`). A single-dash token is a run of one-letter flags (`_problema_cortos()`, pflag's `parseSingleShortArg`): each letter is translated to its long flag and goes through `problema_flag()`, booleans and counters group (`-vn1` is `-v -n -1`), the first letter that takes a value keeps the rest of the token (`-f+ *.md`, `-f=…`) or, with nothing left, the next token, and `=` after a boolean (`-c=false`) ends it. This matters because `-1` is `--resync` in bisync (`cmd/bisync/cmd.go`) and `-n` is `--dry-run`: before #174 short flags passed, so `extra_flags = ["-1"]` was a silent `--resync` on every pass (checked with the pinned v1.75.2: `-1`, `-vn1`, `-L1` and `--checksum -1` all resync). The refusal names the letter and its long flag («'-n' ('--dry-run', en '-vn1') no se admite: …»). A letter the table lacks is read as a boolean and the scan goes on: it is not refused itself (rclone rejects an unknown letter on its own), and a letter rclone knows but the table does not cannot hide a `1` after it. The **value** of a flag that takes one is not read as a flag unless it starts with `--` (as before, conservatively): `["--max-delete", "-1"]` is the documented «no limit» (`frenos.py`), not a resync, while after a boolean (`--checksum -1`) or a `--key=value` token the next one is a flag again. A bare `-` and a token not starting with `-` are positional.
  - **Where the letters and the value-taking flags come from:** `common/flags_rclone.json` (`model.DATOS_RCLONE`, read once by `model._rclone()`, only when a token needs it). `generar_flags_rclone.py` writes its `cortos` table (`{letter: {"flag", "valor"}}`) from **every** section of `rclone help flags` and of each command's `--help`, the Backend group included (`-L` `--copy-links` and `-x` `--one-file-system` are the local backend's; the `flags` table leaves the backend out), without `-h`; a letter of two flags stops the generator. A flag takes a value unless its type is `bool` or `count` (pflag gives those a `NoOptDefVal`). Without the file nothing is known: every token is judged as a flag, which refuses too much (`--max-delete -1` included) and never too little. Moving `RCLONE_VERSION` regenerates it like the rest of the file.
- `model.problema_valor_flag(clave, valor)`: the **values** of `[defaults.flags]`/`[pair.flags]` are checked as `flags_to_args({clave: valor})` emits them, through `problema_extra()`: a boolean flag does not consume the next argument, so `checksum = "--sftp-ssh=sh -c id"` would reach rclone as `--checksum --sftp-ssh=sh -c id` and `checksum = "-1"` (or `-1`, or `["-1"]`) as `--checksum -1`, a resync. The key decides: `max-delete = -1` and `max-delete = "-1"` are values, and so is `exclude-if-present = "-x"`. A value starting with `--` is refused whatever the key, as before.
- `model.problema_local(local, equipo)`: `local` is a folder INSIDE the device, relative to its root. A `local` that is present but not a text (`local = ["a/../../etc"]`, which `_build_pair()` would read with `str()`) is refused by `comprobar_seguridad()` before this. Refused, on the raw text with `\` read as `/`: a `..` segment, a first segment with a drive prefix (`C:`, `d:x`), a segment made only of dots and spaces other than a lone `.` (`...`, `. .`, `.. `), a `:` in any segment (`docs:stream`, `.prdrive::$INDEX_ALLOCATION`: on Windows `name:stream` is an NTFS data stream of `name`), and a first segment equal (case-insensitively, after `rstrip(". ")`: Win32 path normalisation turns `.prdrive.` and `.prdrive ` into `.prdrive`) to the program's folder (`APP_DIR.name`, `.prdrive` on a device: the program, with the key; `carpeta_programa=` overrides it for whoever reads another root's config) or to `LLAVERO_LOCAL` (`.keychain`: the keychain has its own pair). Only the first segment counts for those two names: `sync-data/.keychain` is an ordinary folder. What no text gives away (8.3 short names, junctions, symlinks into the program folder) is stopped at run time by `model.problema_contencion()`. A leading `/` is tolerated on drives (`normalizar_local()` strips it and devices in use may have it). On a host root (`equipo`, passed by `parse_config(equipo=)` and by `agente.leer_servicio()` from `es_equipo()`; the agent also passes `carpeta_programa=APP_SUBDIR`, because there `APP_DIR` is the agent's own folder, not the drive's `.prdrive`) `problema_local_equipo()` goes first and keeps its own words (`host-root.md`). Without it, a drive's `local = "../../fuera"` makes the `combine` upstream `..=<parent>` and `C:/…` leaves the device on Windows. It lives in `comprobar_seguridad()` and not in `_build_pair`, so the agent applies it too.
- `model.problema_remote()` (`NOMBRE_REMOTE`): a `remote` with `,` `:` `=` or quotes, or a leading `-`, is an rclone connection string (`nas,ssh='sh -c id'` is an `sftp` remote with its own command), not the name of a remote of `rclone.conf`. A name of exactly one ASCII letter (`C`, `n`) is refused too: rclone reads `C:path` as the Windows drive C (`fs/fspath/path.go`), so the remote would resolve to a local folder; the message says to rename it with two characters or more. It covers the pair's `remote` and, in `[defaults]`, both `remote` and `catalog_remote` (checked as soon as the key is present, **even when empty and even when every pair has its own `remote`**: an empty default would leave a pair with no `remote` on `:remote_path`, where a crafted `remote_path` is a connection string): `carpeta_del_catalogo()` takes them as they are for the keychain pair and `catalog.endpoint()` for the `rclone cat` of the catalogue.
- `include`/`exclude` (`_comprobar_patrones()`): an entry with `\n` or `\r` is refused, in a pair and in `[defaults]`. `bisync.filters_content()` writes one rule per line, so `exclude = ["x\n!\n+ **"]` would add a lone `!` (rclone resets the rule list, dropping `REGLA_SIN_PROGRAMA`, `REGLA_SIN_LLAVERO` and `- .prversions/**`) and a `+ **`.

`comprobar_seguridad()` works on the **raw** dict (`tomllib`'s output) and tolerates any shape (non-table values, non-text names, no `[[pair]]`) and decides nothing else: an unknown mode or key is not its business. It covers `[defaults]` (`remote`, `catalog_remote` whenever the key is present, `flags`, `extra_flags`, `include`/`exclude`; errors prefixed `[defaults]`) and each named pair (`remote`, `flags`, `extra_flags`, `include`/`exclude`, `local`; prefixed `[<pair>]`). `extra_flags` is checked as `_as_tuple()` will emit it (an inline table gives its keys; a value that is not iterable is a `ConfigError`). `_build_pair` also checks the `remote` that comes out of the fallback chain (`[<pair>]`), so no path skips it. It is the single place for these raw checks: `parse_config()` calls it first, and `agente.leer_servicio()` calls it on the raw TOML it reads (`agent.md`), because a drive whose own `sync.py` predates the rule checks nothing. Every message names the layer, the key or the argument, and says what to do (`QUITALO`, «Quítalo del config.»): a refused config is a `ui.fatal` and is fixed by hand. The keychain pair is built by code and not checked: it keeps `resync-mode`. `ui/flags_editor` re-exports `RESERVED` and `normalize` and calls the same functions (`problema_flag`, `problema_valor_flag`, `problema_extra`), so the dialog says it while typing; `tests/test_parseo_seguro.py`.

**A missing local folder is never created empty when it is the SOURCE of a `sync`** (#151). `Mode.borra_en_remoto` (`verb == "sync"` and `origen_local`: `up-mirror`) names the rule. `rclone sync` with a source that does not exist fails with `directory not found` (rc 3) and deletes nothing, but with an empty one it makes the remote a copy of nothing: `--max-delete 50` removes 50 files per pass (rc 7) and the next passes go on until the remote is empty, and neither `runsync.py` nor the agent reads the brake's finding to stop them. So `_pasar_pareja()` does not take its general «create the local folder» step for that mode: it prints the error, `record_result()`s rc 2 and returns, exactly like the bisync abort (`--force` and `--dry-run` included: the pass is the same one). `revision._local` words the same case as GRAVE (`repair.md`). A new `up-mirror` whose folder does not exist yet fails the same way, on purpose: there is nothing to upload and creating it is what deletes. Nothing creates the folder for it (`pair_editor`, `deploy`); a person does. `down`, `down-mirror`, `up` and a bisync without a baseline still create it: in a download it is the destination, an `up` is a `copy` and never deletes, and a bisync without a baseline has no listing to compare against. An existing but empty folder is not touched by this rule (the brake and «Forzar sincronización…»'s warning cover it, `repair.md`).

**Runtime containment: `model.problema_contencion(pair)`.** No text check sees where a `local` really lands: an 8.3 short name, a junction or a symlink can take an innocent-looking `local` into `.prdrive/` (the key), where a `down-mirror` would delete it. `run_pair()` therefore asks, before anything else (also for non-bisync pairs, which have no preflight), whether the resolved `local_abs` or `top_level_abs` IS `model.APP_DIR.resolve()` or is inside it, and if so aborts that pair with rc 2 and a message, recorded like the other aborts (`record_result()`). A root pair (`local = "."`) contains the program folder but is not inside it, so it passes (it carries `REGLA_SIN_PROGRAMA`). There is deliberately **no** general «outside the device» check: a host root may symlink out on purpose (`host-root.md`). `tests/test_parseo_seguro.py` (POSIX; prints `(saltado)` where symlinks cannot be made).

## bisync (`common/bisync.py`)

The one place that imitates rclone's behaviour; each section cites the rclone source it mirrors. **Preserve the citations.**

- **Session prefix.** `canonical_path`/`session_name`/`expected_prefix` replicate `cmd/bisync/bilib/canonical.go`, so the listing name is known **before** running. Used by `pair_editor` (does this baseline still belong to this pair?), `revision` (the «prefijo» finding, `--doctor`) and the keychain (`llavero.listado_local()`). `FsPath` writes `name:` + the backend's `Root()`, which is the path as given except for an rclone remote of `type = local` in the device's `rclone.conf` (`bisync.tipos_de_remote()`, read with `pairing.parse_rclone_conf()`): its `Root()` is `cleanRootPath()` (`backend/local/local.go`), replicated by `raiz_local()` and checked against rclone v1.75.2. On Linux, each segment other than `.`/`..` goes through `encoder.OS.FromStandardName` (`Base`: `EncodeZero | EncodeSlash | EncodeDot`), the path is cleaned (`a//b`, `a/./b` → `a/b`), and `Root()` turns each segment back into the Standard encoding (`ToStandardPath`; `Standard` adds `EncodeCtl | EncodeDel`): a lone `.`/`..` is `．`/`．．`, a control character is its symbol (`\x0b` → `␋`, `\x7f` → `␡`, NUL → `␀`), and a quote rune `‛` (or a symbol that was already there) is quoted with another `‛` (`it‛s` → `it‛‛s`). `_codificar()`/`_decodificar()` replicate `MultiEncoder.Encode`/`Decode` (`lib/encoder/encoder.go`) for those two masks only; the Windows encoder (`lib/encoder/os_windows.go`) is **not** replicated, because it has not been checked against a Windows rclone. A local side **without** `device_remote` is the unnamed `local` backend, so on POSIX it goes through `raiz_local()` too. `CanonicalPath`'s `\s` is RE2's (`[\t\n\f\r ]`), not Python's Unicode one: `_NON_CANONICAL` spells it out, so `\x0b`, `\x85`, `\xa0` or a full-width space stay in the session name as rclone leaves them. Before #174 any of these in a device label, a folder or a remote path gave a prefix rclone never writes: `referencia_vacia()` never rebuilt an empty reference, `revision` flagged a good baseline as someone else's («prefijo») and its plan would shelve it, and the keychain never found its listing. `tests/test_bisync_prefijo.py` pins the cases with the values the rclone v1.75.2 code itself returned (`bilib.CanonicalPath`, a `type = local` remote's `Root()` through `fs.NewFs`, `bilib.SessionName`, called from a small Go program against that module); 4000 random paths over those characters matched it with no difference. `tests/integracion/prefijo_alias_real.py` adds, on Linux only, a real `bisync --resync` to a `local` remote whose folder has a full-width space, `\x0b`, `\x85`, `\xa0` and `\x1c`. Not with `‛`: rclone reads the path it is given in the Standard encoding, so it doubles a real `‛` when opening the folder too and answers `directory not found` (seen with v1.75.2); such a folder cannot be synced as written, and only the oracle values pin its name. On Windows (`bisync.IS_WIN`), absolute from `APP_DIR` (rclone's cwd) and long-path: `D:\x` → `//?/D:/x`, `\\srv\x` → `//?/UNC/srv/x`, unless `nounc = true`. Without it, a Windows pair with a `local` remote expected `nas_D__…` where rclone wrote `nas_____D__…`: passes ran (`pair_state()` globs), but the keychain never found its listing and `revision` would call the baseline someone else's (found by `llavero-real.yml`). `type = alias` is the other exception (next bullet); every other backend is `name:` + the root as given. `tests/_harness.sandbox()` moves `RCLONE_CONF` too, so no test reads the checkout's.
  - **An `alias` is named by its target, not by itself** (`bisync.resolver_extremo()`, #37). An alias has no `Fs` of its own: its `NewFs` returns the target's (`cache.Get(ctx, fspath.JoinRootPath(opt.Remote, root))`, `backend/alias/alias.go`), so `FsPath` sees the *target's* `Name()` and `Root()`. Pair `pruebas:datos/prueba` over `[pruebas] remote = C:\prdrive-pruebas\remoto` is listed as `…C__prdrive-pruebas_remoto_datos_prueba` (seen on Windows), never `…pruebas__datos_prueba`. The replica follows rclone: `_partir_remote()` is `fspath.Parse` (the `remote` option as a path or `name:path`; on Windows one ASCII letter before `:` is a drive, `fs/driveletter`), `_unir_raiz()` is `fspath.JoinRootPath` (the pair's root is made absolute first so it cannot climb out of the alias, then `path.Join`ed; a leading `//` is kept), and the target is rendered by kind: a bare path is rclone's backend `local`, whose `Name()` is literally `local`, so `FsPath` writes it **with no `name:`** and with the OS separator (`fs_path_local(raiz_local(...))`); a remote of `type = local` keeps its name and its `Root()` (`raiz_local()`); another alias is followed (at most `TOPE_ALIAS` hops, rclone has no limit and just overflows its stack on a cycle); anything else is `name:` + the joined root. `crypt`, `union`, `combine`, `chunker`, `hasher` and `compress` need none of it: each overrides `Name()` and `Root()` with its own section name and root (`backend/<name>/<name>.go`; names written by rclone v1.75.1 are pinned in `tests/test_bisync_prefijo.py`, and `tests/integracion/prefijo_alias_real.py` compares them with the real rclone on Linux and Windows in CI).
  - **What cannot be followed is not guessed.** An alias with no `remote`, a cycle, a target that is not in `rclone.conf` (it may come from the environment) or a connection string (`:backend:path`, `name,opt=v:path`: out of scope) makes `resolver_extremo()` return `None`. `expected_prefix()` stays total (it keeps the endpoint as written) but `bisync.prefijo_comprobable(pair)` is then `False`, and `revision._prefijo()` says nothing in that case: **a false diagnosis is worse than none**, and the «Apartar el baseline…» button would shelve a good baseline for no reason. `--doctor` prints «no se puede comprobar» on the `prefijo esperado` line instead. There is deliberately no `NOTA`: its chip reads «se arregla sola», which this never does.
  - **The target of an alias is now part of the prefix**: changing `remote` of the alias in `rclone.conf` is a change of endpoint, like `remote_path`. «Reparación» then reports the old baseline as someone else's and its plan shelves it (never renames it, as above). Devices already using an alias need no migration: rclone has always written their baseline with the resolved name, and what was wrong was the diagnosis.
  - **`rclone.conf` is read once per decision, and never cached.** `bisync.tipos_de_remote()` reads and parses the file on every call, and resolving a pair's two ends used to call it once per end (`expected_prefix()`, `prefijo_comprobable()`, `referencia_vacia()`). `resolver_extremo()`, `fs_path_remote()`, `expected_prefix()`, `prefijo_comprobable()` and `referencia_vacia()` take an optional `tipos=` (`None` reads the file there; `{}` is a file with no remotes, not «unread»), and `referencia_vacia()`, `revision._prefijo()` and `revision._informe_pareja()` read it once and pass it on (`sync.run_pair` goes from 4 reads per bisync pair with `device_remote` to 1, `--doctor` from 10 to 2). There is deliberately no `(path, mtime)` cache: with FAT's 2 s mtime granularity a window left open for hours could serve a stale `alias` target, report a false «the baseline is not this pair's» and offer to shelve a good baseline. `tests/test_bisync_prefijo.py` counts the reads.
- **`device_remote`, on by default** (`DEFAULT_DEVICE_REMOTE = "disp"`; `deploy.device_config()` `setdefault`s it into each new device's `[defaults]`). It makes the device side a `combine` remote via `RCLONE_CONFIG_<NAME>_TYPE/_UPSTREAMS` (`Config.pen_environment()`, built from **all** pairs), so the prefix is machine-independent; `alias` does not work. It belongs to the **device's** defaults: in the catalogue it would move every installed device's prefix at once.
- **Quoting `upstreams`.** rclone parses it as an `fs.SpaceSepList` (`fs/types.go`): space-separated CSV, a field quoted only if it **starts** with a quote. So the quotes wrap the whole `name=path`, never just the path: `.="F:\"` gives `bare " in non-quoted-field` and takes **every** pair of the device down. They exist for a drive root's trailing backslash and for spaces. `model._upstream()` is the only builder.
- **The device root needs a named upstream.** rclone cleans the path first, so `local = "."` becomes upstream `""` and fails with `combine for remote "": directory not found`. `model.RAIZ_UPSTREAM` (`"raiz"`) names it, hence `top_level_dir` (the name) and `top_level_abs` (the folder). The name is part of the prefix: changing it invalidates those baselines.
- **No listing rename** (`normalize_prefix`, `rename_prefix`, `heal_listings` were deleted with `device_remote`). Renaming a listing set tells bisync that a listing of the *previous* destination describes the *new* one, and the benign case is indistinguishable from the malignant. Legacy devices are fixed by hand; no migration code. `tests/test_bisync_prefijo.py` asserts the absence and guards both halves of `device_remote`.
- **Filters.** bisync only (`Pair.wants_filters_file`): `filters_file_for()` writes `filters/<pair>.txt` (atomically: `_escribir_filtros()` renames a temp file over it, because the window regenerates it from a thread while another screen reads it) and passes `--filters-file`; `--include`/`--exclude` are then **not** also emitted (duplicate rules break change detection). Code-owned rules (`Pair.reglas`: the keychain's; and on every root pair, `local = "."`, `REGLA_SIN_PROGRAMA` (`- /<APP_DIR.name>/**`) followed by `REGLA_SIN_LLAVERO` when `[keychain]` exists, `llavero.md`) go right after `- .prversions/**`, before the TOML's; outside bisync they become `--include`/`--exclude`. bisync rewrites the md5 beside the file only on `--resync`, so `filters_state()` compares the hash itself and reports "needs resync".
  - **A root pair never carries the program's folder.** Without `REGLA_SIN_PROGRAMA` a `local = "."` pair uploaded `.prdrive/` (the SSH key in `keys/`, `rclone.conf`) and a root `down-mirror` would delete it. `parse_config()` builds the root rules once and gives them to every root pair; the user's TOML cannot remove them, and a `+` of the pair comes after them. The rule is the program folder's name, so a device's `.prdrive/` and a dev checkout's folder each exclude their own. **Outside bisync it is an `--exclude`, and rclone puts every `--include` before every `--exclude`** (`fs/filter/filter.go`, `NewFilter`; see `orden.filter_args()`): a copy/sync root pair whose own `include` matches the program folder still carries it, the same gap `llavero.md` words for the keychain rule. In bisync the rule precedes the pair's `+` rules, so there is no such gap.
  - **A root bisync pair that predates the rule needs one `--resync`**: its filters file changes, so `filters_state()` says `changed`, the window offers the resync, and the service and the agent skip the pair until then (the agent says so once and the tray keeps listing it as «necesita --resync»: `Agente.saltadas`, `agent.md`, `tray.md`). Non-bisync root pairs need nothing. **Nothing deletes a copy that already reached the remote**: `bisync.programa_en_listado()` looks for the folder in the baseline's `path2` listing (best effort: missing or unreadable means no), and `revision.carpeta_programa_en_remoto(pair)` is the ONE decision built on it (`es_raiz` and listed → the remote folder, built from `remote_name` and `remote_path` as they are: `""` is `nas:.prdrive/`, `"/"` is `nas:/.prdrive/`, `"R/p/"` is `nas:R/p/.prdrive/`, since relative and absolute differ in SFTP). It is said **before** the resync, on purpose: afterwards the new listing no longer shows the folder, and the resync is approved in three places that all ask `carpeta_programa_en_remoto()` and print `revision.aviso_carpeta_programa()`: the pair's `resync` finding (`dato`, detail; `repair.aviso_resync()` in «Reparación»), the main window's prompt (`ui.manual_args()` → `ui.carpetas_del_programa()` → `tk.preguntar_resync()`) and `sync.resolve_resync_approval()` (console, also with `--yes`).
- **State.** One workdir per pair, `Pair.workdir` → `state/<pair>/` (`migrate_legacy_state()` moves the old flat layout). `pair_state()` → `PairState(status, detail, prefix)`, `fresh|ok|broken`, read from the real `.lst` files. `resync_reasons(pair)` = why a pair needs `--resync` (`[]` for non-bisync; the mode guard is inside). `last_run(pair)` = mtime of the newest listing = the last good pass (None for non-bisync).
  - A `.lst-err` is the baseline rclone sets aside when a pass aborts (`cmd/bisync/operations.go`, `markFailed()` in `lockfile.go`; with `--recover` the next pass goes back to `.lst-old` and leaves them). The state line says what they are and that they may be deleted by hand; **nothing deletes them**: bisync's workdir is not ours to clean.
- **Resync approval.** `resolve_resync_approval()` asks **once** for all pairs before anything runs; `ask_yes_no()` returns the default when stdin is not a tty, so non-interactive runs skip those pairs (`SKIPPED = -1`) rather than resync unattended.
  - **The one exception is the keychain pair** (`pair.llavero`): `_bisync_preflight()` resyncs it whenever `resync_reasons()` says so, unasked, and it is left out of the question, of `ui.pair_status_notes()` and of `revision`'s `resync` finding. Its `resync-mode = newer` keeps the newer base and the backup dir catches the other side's (a `--resync` honours it too), so nothing is lost; skipping it would leave it silently unsynced, since a skipped pass exits 0. The «local path missing with a baseline» abort still runs first. It also resyncs, once and after `rclone mkdir`, a normal pass that stopped at «Empty current Path2 listing» (its remote folder deleted by hand; with `resilient` rclone keeps the listings and that pass would fail for ever): `sync.repetir_sin_freno()`, `llavero.md`. A user pair with an empty remote still waits for a person.
  - **The other exception is a pair whose reference is empty** (#113; `bisync.referencia_vacia()`, `tests/test_referencia_vacia.py`). `--resync` on two empty sides leaves both `.path1.lst`/`.path2.lst` without an entry, and rclone then aborts every later pass that is not a resync (`checkListing()` in `cmd/bisync/listing.go`, called from `findDeltas()` on the prior and the current listing of each side: «Empty prior Path1 listing», rc 7, «retryable» but never fixed by retrying), because it cannot tell an empty folder from an unmounted one. In v1.75.1 only `--resync` skips that check; `--force` is not consulted there. `_bisync_preflight()` redoes the baseline with `--resync`, unasked and also unattended (agent, `--auto`), when `bisync.referencia_vacia()` says so (the three conditions below); the line «la referencia está vacía: se rehace…» says why. Nothing is left in the reference to protect and a `--resync` deletes nothing, so no approval is asked. It is still not «do nothing while it stays empty»: the remote may have received files from another device meanwhile, and the resync is what downloads them. Each pass is a resync until a listing has an entry.
    - **`referencia_vacia()` is the whole decision**, and the pass, the pass report and `--doctor` all ask it, so none of them can promise what another does not do. It needs: (1) **the baseline is this pair's**, `state.prefix == expected_prefix(pair)`. If an end changed without shelving the baseline (hand-edited TOML, an `alias` target, another drive letter on a device without `device_remote`) rclone would not find those listings, and an unattended `--resync` against the new ends would mix the local folder with the new destination without asking and leave a second set of listings, so `pair_state()` would read «varios juegos de listados» and the pair would end `broken`: that stays «Reparación»'s `prefijo` finding and a person's `--resync`. A prefix that cannot be checked (`bisync.prefijo_comprobable()`: an `alias` that `resolver_extremo()` cannot follow, see above) proves nothing even when the names agree, since `expected_prefix()` is then an estimate; such a pair never gets the exception and goes on as before. (2) **The local folder exists**: the abort «baseline but no local folder → rc 2» stays where it was, untouched, and this function simply says no while the folder is missing, so such a pair reaches that abort exactly as before; the folder is never created empty to resync it. (3) **Both listings are empty.** With one empty and the other not, nothing changes: a side emptied since the last good pass is exactly what rclone must stop.
    - **What counts as an empty listing** mirrors `fileList.empty()` on what `loadListing()` keeps: blank lines and `#` lines (the `# bisync listing v1 from …` header) do not count; a file (`-`) or a folder (`d`, from `create-empty-src-dirs`) does. A line rclone would discard as malformed counts as content here, on purpose: wrongly answering «empty» redoes a baseline that had something to protect, wrongly answering «not empty» only leaves today's failure. A listing that cannot be read is not empty.
    - **Accepted risk**: if between the initialisation and this pass a file with the same name appears on both sides, the resync keeps one (the pair's `resync-mode`, `path1` if it has none) and the other survives only if the pair has `versions` (`.prversions/`). The same goes for a listing cut down to its header by a crash. Measured on 2026-10-15 with rclone 1.75.1 and a `local` remote in a temp dir (device version vs. remote version, no `versions`): `path1`, the device, won and replaced the remote's, and the pass then failed with «Modtime not equal in listing» (rc 7, listings set aside as `.lst-err`), exactly as a manual `--resync` does on code without this exception (3 of 3 runs). The pair then waits for a person's `--resync`, as any pair with a broken baseline. Not measured on SFTP.
    - **It is not a «moved» pass**: `_bisync_preflight()` returns the decision with `need_resync` (`(need_resync, vacia, abort_code)`), so it is taken once, and `_pasar_pareja()` does not tell `parte.Medida` that it is a resync when the reference was empty, so one that finds nothing reports `movio = false` and the agent keeps stretching that pair's interval (`planificador`) instead of treating an empty pair as busy for ever. One that brings files changes the listings and reports `true` as always.
    - **`--doctor`** prints `referencia: vacía — la próxima pasada la rehace` under the pair's `estado:` (`revision._informe_pareja()`). It is not a finding of the ONE diagnosis, because the pass fixes it alone, and it appears only when the pass will: with the local folder missing, `--doctor` says nothing about it and the `local` finding («la carpeta local no está») is what explains the rc 2. `resync_reasons()` is untouched, so the question of `resolve_resync_approval()`, `ui.pair_status_notes()` and `revision`'s `resync` finding can still list such a pair if its filters also changed; the pass resyncs it anyway.

## Logs and live progress

rclone writes to a temp file; `dispose_log()` keeps it in `logs/` only if the run failed (or `--keep-logs` / `keep_logs = true`), to spare device write cycles. Only the newest `LOGS_POR_PAREJA` (20) logs per pair are kept: `keep_log()` calls `podar_logs(name, final)` once the move into `logs/` has succeeded, ordering by the stamp in the file name (date, time, then the `_N` retry suffix as an integer), not by mtime, and it never raises. The log just saved is exempt from the ranking and counts toward the 20 (stamps are local time: a clock set back would rank it oldest and the pass would lose the very log `last_run.json` points at); with `keep_logs = true`, logs of good passes share the 20 with the failed ones. On failure the tail is printed and `KNOWN_ERRORS` maps rclone messages to an explanation: add new cases there.

Device vanished mid-pass (#36): `keep_log()` leaves the log in the temp dir, says so in one `AVISO` line (any half-copy in `logs/` removed) and returns that path, so tail and explanation still come out. `run_all()` turns an `OSError` from the pairs after it into a `FALLÓ` line, never a traceback.

- `--log-file` only catches what rclone logs **after** installing the log, so `execute()` captures rclone's `stdout`+`stderr` (captured, not inherited: with no console behind it, inherited output is lost) and `append_output()` appends it under `DIRECT_OUTPUT_HEADER`.
- `strip_usage()` drops the 12 KB help dump rclone prints after a bad flag: it mentions `--max-delete` and `lock file`, so `explain_failure()` matched a `KNOWN_ERRORS` needle inside rclone's own docs. **A false diagnosis is worse than none.** The flag entries of `KNOWN_ERRORS` (`unknown flag`, `invalid argument`) go **last**, and the delete brakes' needles are exact functions from `common/frenos.py` (`frenos.ENTRADAS`), not the bare `--max-delete`, which also matched `--max-delete-size` and rclone's own help.
- **Known log noise, not a failure: `Failed to set sparse: FSCTL_SET_SPARSE: Incorrect function`.** On Windows rclone writes it for each large download to an exFAT drive: its multi-thread downloads make sparse files, and exFAT has none. The file comes out right. No `KNOWN_ERRORS` needle matches it, and nothing else reads it: `progress` matches only rclone's stats line and `parte` only the transfer lines it counts. The real-machine run of 24/09/2026 recorded no effect on the result (`docs/superpowers/pruebas/2026-09-24-veracrypt-unidad-g-resultados.md`). Those notes do not record rclone's exit code for that pass, so the claim rests on the observed result. If the line shows in the tail of a failed pass, it is not the cause: read the line above it. Do not add `local-no-sparse` to `BASE_FLAGS`: on NTFS it turns big downloads into long pauses while the system zero-fills the file.
- A needle matches rclone's **error**, never a routine line that also appears in passes that fail for another reason: bisync logs `lock file renewed` on every pass (hence `prior lock file found`), and sftp logs `No host key validation is being performed. Set known_hosts_file …` on every pass to a remote without one (hence `couldn't parse known_hosts_file`, `NewFs` in `backend/sftp/sftp.go`).
- Needles are **case-sensitive** and must be what rclone writes: bisync's critical abort is `Bisync aborted. Must run --resync to recover.` (and `Bisync interrupted. …`), capital `M` (`cmd/bisync/operations.go`, v1.75.2); a lowercase `must run --resync` needle never matched it (#174). That needle goes **after** every needle of a concrete cause: the abort follows the cause (a device not ready, a lock, the network), and the filters errors carry their own lowercase `(must run --resync)` (`cmd/bisync/cmd.go`), so it only explains an abort nothing else recognised.
- **Live progress.** `BASE_FLAGS` has `--stats 2s --stats-one-line` (base layer, so a pair can override it); `execute()` runs rclone inside `seguir_progreso(logfile)`, a thread tailing the temp log: the **only** channel, no rc API or ports. Strictly best-effort: an unmatched line gives no progress and the thread swallows *any* exception.
  - The file is closed before `execute()` returns (Windows cannot delete or move an open file); `main()` line-buffers stdout (behind the window it is a pipe); `print_log_tail()` drops stats lines.
  - The regex mirrors `StatsInfo.String()` (`fs/accounting/stats.go`) and requires the ETA, so a line cut mid-write never yields a half number.
- **The pair's report for the agent** (`common/parte.py`, `tests/test_parte.py`). `run_pair()` ends every real pass (never a dry run) with one line `@prdrive {"pareja", "rc", "movio", "ordenes", "escrito"}`, after what a person reads: `rc` is the pair's code (`-1` skipped; the line never contains the word «saltada», which the agent searches for), `ordenes` how many times `execute()` ran rclone for it, `escrito` the bytes of its bisync workdir files whose size or mtime changed, and `movio` whether the pass changed anything on either side: `false` only when that is known, `null` when it is not (a failed or skipped pass, a non-bisync pair whose log says neither). For bisync it compares the two listings **without their first line** before and after (`parte.base()`, `Medida`): rclone rewrites them whole on every pass and with nothing changed only the header date differs (measured with 1.75.1); a `--resync` always counts as moved, and so does a pass that leaves fewer than two listings. For `copy`/`sync` pairs it reads the log before `dispose_log()` (`sin_actividad()`): quiet needs rclone's `There was nothing to transfer` **and** no `Copied`/`Deleted`/`Moved`/… line (a mirror deletes without transferring); a log over 256 KB is not read. Measuring never fails a pass (`Medida` swallows its own errors). `parte.leer()` ignores anything it cannot parse, so the output of an older `sync.py` just yields no report.

## Writing the TOML (`common/config_file.py`)

`tomllib` only reads and the project has no deps, so the serializer is hand-rolled: scalars, string arrays and one nested `flags` table. Preserve:

- `[pair.flags]` binds to the **last** `[[pair]]` written, so it is emitted right after its pair.
- `dumps_checked()` re-parses its output and refuses to write if the dict does not reproduce. `save()` and `catalog.push()` both go through it.
- **A table it does not know** (not in `TABLAS_CONOCIDAS`, e.g. a newer version's `[keychain]`) is written as is at the end. `model.parse_config()` ignores it on read, and dropping it on write would make `dumps_checked()` refuse the whole file, so a catalogue carrying it could not be edited. A subtable inside it is still refused by that check.
- Work on the **raw dict**, never `model.Config` (its `Pair`s have `[defaults]` merged). `save(head=None)` keeps the target's header.
