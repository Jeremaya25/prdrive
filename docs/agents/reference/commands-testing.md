# Commands, verification and test conventions

Formerly AGENTS.md «Commands» (full list), its verification notes, and the registry of indirection points from «Conventions».

## Commands

```bash
python sync.py [pares...]      # every pair in sync_config.toml, or only these
python sync.py --list          # pairs + resolved endpoints (safe, read-only)
python sync.py --doctor        # bisync state: prefixes, filters, locks
python sync.py --dry-run       # simulate; MANDATORY before any *-mirror run
python sync.py --resync        # rebuild the bisync baseline
python sync.py -y/--yes        # auto-approve the resync question (cron/scripts)
python sync.py --keep-logs     # keep logs of successful runs too

python runsync.py              # UI (Tk, console fallback) + periodic service
python runsync.py --auto       # periodic service with the service's config, no UI
python runsync.py --auto --once  # one pass of the service's pairs, then exit
python runsync.py --llavero   # «Abrir llavero» without the window (what Llavero.bat runs)
python runsync.py --vigilar-llavero  # the keychain watcher (started by «Abrir llavero»)
python runsync.py --combinar-llavero BASE COPIA [--keyfile K] [--sin-contrasena]  # the «Combinar» console
python runsync.py --convertir-llavero BASE LLAVE [--actual K]  # the console that leaves a base key-file only
python runsync.py --cerrar-llavero   # what Expulsar PRDRIVE.bat runs before dismounting
python runsync.py --doctor     # any other args pass straight through to sync.py

python penwatch.py install|status|probe|uninstall   # the watcher, per machine/user
python agente.py run|status                         # the resident agent (host copy)
python agente.py atender ID | modo ID MODO | pasada ID [pareja…] | pausa | sigue | parar
python agente.py abrir [ID]                         # the window of the host root (the menu entry;
                                                    # starts a stopped agent, and with no root says how it is)
python agente.py desbloquear [ID] | bloquear [ID]   # open / close the encrypted host root
python agente.py ajuste pedir_al_iniciar sí|no      # or espera_unidad_nueva SEG
python agente.py actualizar                         # fetch the new release and put it in place
python agente.py actualizar ID                      # put that root on the agent's version (the tray's «Actualizar a la vX»)
python agente.py expulsar ID                         # release that removable drive (the tray's «Expulsar»)
python pregunta.py --nombre N --segundos S [--cambiada]  # the «¿Atender esta unidad?» window, what the agent
                                                    # launches (`agente.py pregunta` is the fallback if it is missing)

python prdrive-install.py          # install wizard for a NEW device (Tk only)
python prdrive-install.py --check  # rclone + connection + catalogue, then exit
python prdrive-install.py --probe  # what drives it sees, then exit
python prdrive-install.py --update E:\             # the device's code only
python prdrive-install.py --update-components E:\  # its rclone + runtime only
python prdrive-install.py --instalar-agente        # the resident agent on THIS host
python prdrive-install.py --desinstalar-agente     # and off again (no drive touched)
python prdrive-install.py --update-agente          # the installed agent (and open host roots) to this version
python build_installer.py          # build the .exe (embeds the profile if any)
python -m ui.icons                 # repaint APP_DIR/runsync.ico (headless)

python tests/run_all.py            # all tests; or run one script directly
python tests/_runtime_ci.py clave|runtime PLAT DESTINO CACHE  # the CI's pinned Tk 9 runtime (key / fetch)
python tests/rendimiento/correr.py --pr DIR --base DIR --trabajo DIR [--python PY] [--rondas 7] [--capturas]  # the timing check (CI)
python tests/integracion/llavero_real.py --de-verdad  # the keychain end to end, for real (CI only)
python tests/maquina/correr.py --lista           # checklist rows with a cloud real-machine test (F9, F14…)
```

`runsync.py` with no args always **stops a previously started service** first.

## Verification

Verification is `tests/run_all.py` (each script in its own process), `--doctor` and `--dry-run`. Nothing to lint. CI (`.github/workflows/tests.yml`) runs `run_all.py` on every PR and push to `main`, **twice**: job `tests` on `ubuntu-latest` under `xvfb-run` (with `python3-tk`) and on `windows-latest`, `setup-python` 3.11 (Tk 8.6: the minimum, and where the Python painter is the fallback); job `tests-tk9` on the same two systems with the device's pinned runtime (`common/pins.py`: Python 3.14.8, Tk 9.0.4), the only place the SVG path runs (`tests/test_iconos_svg.py` compares it with the Python painter; `ui.md` «Icons carry alpha»). `PRDRIVE_SIN_SVG=1` makes `ui/icons.py` use its Python painter on a Tk 9 too (`icons.USAR_SVG = False`, read at import): `PRDRIVE_SIN_SVG=1 xvfb-run -a <runtime>/bin/python3 tests/run_all.py` runs the whole suite through the Tk 8.6 path with the Tk 9 in place. That runtime is fetched in a step before the suite (the suite never touches the network) by `tests/_runtime_ci.py`, which uses the installer's own `runtime_bin` (SHA-256 checked against the release's `SHA256SUMS`) and leaves the interpreter in `PRDRIVE_PYTHON`; Actions caches the archive under `runtime-<plat>-<key>`. Each leg runs as an unprivileged user (a check that writes to `/` fails there), and no test may depend on what the real `%LOCALAPPDATA%` caches hold. The PR template still asks how it was checked. Tk tests skip themselves without a display, so an all-green run without Tk has tested no window.

**The keychain for real** (`.github/workflows/llavero-real.yml`: PRs touching the keychain, and by hand) runs `tests/integracion/llavero_real.py` on `ubuntu-latest` (xvfb) and `windows-latest`. It is not a `test_*.py` (`run_all.py` never sees it) and refuses to run without `CI` or `--de-verdad`: it downloads the pinned rclone and KeePassXC, provisions a device in a temp dir with `install/deploy` and a `local` remote, and drives the device's own code one step per process (activate, «Abrir llavero», a save the watcher uploads, a real two-sided conflict merged by `plan_combinar()` with the password on stdin instead of a console, the deletion the delete brake must let through, `--cerrar-llavero`, then the key-file-only premises with the real CLI: `db-edit`, the `ls --no-password` probe, `merge --no-password`), checking what KeePassXC itself writes: the HKCU keys and the JSON it rewrites at start on Windows, the manifests on Linux, and a `change-public-keys` through the proxy they name. On Linux it points `HOME` and the XDG dirs at the temp dir. The cloud run that found the bugs it now guards: `docs/superpowers/pruebas/2026-10-05-llavero-nube-resultados.md`.

**Real-machine rows in the cloud** (`.github/workflows/maquina-real.yml`: a push to a non-`main` branch touching `tests/maquina/**` or the workflow, PRs touching what they test, and by hand with `inputs.pruebas` once the file is on `main`) run `tests/maquina/correr.py` on `ubuntu-latest` (as root) and `windows-latest` (as admin). One module per row of the real-hardware checklist (`fNN_*.py`: `CODIGO`, `SISTEMA`, `QUE`, `probar(p)`), checking only the OS boundary: real filesystems on virtual disks (loop, VHD via `diskpart`), the real tray window, VeraCrypt installed with `choco`, a network share of the machine itself, `max_user_watches`. The log ends with one `RESULTADO <code> <W|L> ok|parcial|fallo|saltada …` line per row; results go to `docs/superpowers/pruebas/maquina-real-resultados.md` and an `ok` row is marked `· nube: ok` in the checklist, not removed. How to run and read it cheaply: the `real-machine-tests` skill (`.claude/skills/`).

- The suite passes on Windows **and** Linux. A check about the other system's branch forces it (`IS_WIN`, and for a Linux mount point `Unidad.letra`) in any system, or prints `(saltado) …` when it cannot run there (Unix sockets, the Linux tray's `select()` on a pipe).
- `tests/_harness.py` points `equipo.DIR`, `XDG_DATA_HOME`/`XDG_CONFIG_HOME`/`XDG_CACHE_HOME` and `keepassxc.bases_navegador()` (the browsers' manifest folders, Firefox's under the home folder) at temp dirs for every test, so no test sees or deletes the runner's agent, menu entries, extracted KeePassXC or browser manifests, and turns `os.kill(pid, 0)` into a real question on Windows: there 0 is `CTRL_C_EVENT`, a Ctrl+C to the whole console, and forcing `IS_WIN = False` reaches it.
- **`tests/_vista.py` reads what a Tk screen shows**, for tests that compare two screens (an in-place update against the same screen drawn again): `a_la_vista(widget)` (the widget and every ancestor below its toplevel have a geometry manager; a `grid_remove`d frame hides its children), `visibles(raiz, clase, texto)` and `leer_vista(raiz)`, one tuple per visible widget, depth-first, in reading order (`grid` by row and column, `pack` in packing order, `place` by position; ties broken by class, text, style and image, never by creation order). It reads class, text, style without `Sobre<RRGGBB>.`, ttk state minus `ESTADOS_IGNORADOS` (`active`, `focus`, `hover`, `pressed`, `alternate`, `background`, `user1`–`user3`), image name, cell, `wraplength` and the value of the bound variable; not widget names, padding, child windows, or the root's own cell. It asserts nothing. `tests/test_tk_vista.py`.
- **A path the code under test will open is a `tmpdir()`, never a drive letter or a fixed absolute path.** The harness cannot redirect a path a test writes into the settings: `test_install_agente` registered a locked encrypted root at `P:\` (the letter the wizard proposes), and on a dev machine with a real prdrive mounted at P: `actualizar()` saw its control file and deployed the checkout's code onto it. A letter is fine only where a fake answers for it (`expulsar`, `veracrypt_command`, log lines). Likewise a check that depends on this host's CPU or OS picks its platform explicitly, or empties the cache it reads: on Windows ARM64 «the Linux of this CPU» is `linux-arm64`.
- **Pixels are read where they can be.** `tests/test_superficie.py` checks every rounded control's four corner pixels against its surface by capturing the window with ImageMagick's `import` (X11 only, 24-bit screen, `imagemagick` in the Linux CI steps); anywhere else it prints `(saltado) …` and the half that asks ttk (`style.lookup(style, "background", state)` for the live widget) still runs. The two-pixel-radius pieces (`FINOS`) come out blended with their border and are compared against the proportion measured on the paper.
- Tk 8.6 (system Python) vs Tk 9.0.4 (the Linux runtimes): see «The UI is measured on both» in `provisioning.md`.

## Timing check

`.github/workflows/rendimiento.yml` (PRs touching `ui/`, `common/`, `install/`, `runsync.py`, `sync.py`, `agente.py`, `pregunta.py`, `penwatch.py`, `prdrive-install.py`, `build_installer.py` or `tests/rendimiento/**`, and by hand) runs `tests/rendimiento/correr.py` on Windows x64 and Linux x64 with the pinned runtime (Windows ARM64 only by hand: tick «arm64»). Not a `test_*.py`: `run_all.py` never collects it. Its pure part, the verdict, is tested by `tests/test_rendimiento_informe.py`.

- **How:** the PR tree and its base tree (two checkouts) are measured **in the same job, with the same interpreter and the same driver** (`driver.py`, from the PR tree: it knows how to reach each screen, the tree only supplies code). One round is one pass of each tree and the order alternates between rounds, so a drift of the machine hits both. Each pass is a cold process on a fresh copy of a sample device (5 or 50 pairs, `dispositivo.py`), with a fake `HOME` and a deadline (the whole process tree is killed). Flows (`PLAN`): «Parejas» and «Ajustes» with 5 pairs, with 50 and at 150 % (`tk scaling 2.0`), the main window (`principal`) with 5 and 50 pairs at 100 %, the wizard, the agent's question and the pass window with 10 000 lines. `suelo.py` times an empty Tk window to normalise. `--capturas` leaves one PNG per screen, which proves the machine paints.
- **What fails a PR** (`informe.py`): (1) a deterministic count above its ceiling in `presupuesto.toml` `[techo]`/`[techo.<system>]` (widgets per screen with 5 and 50 pairs, `<<ThemeChanged>>` passes when opening screens, ttk styles created after the first widget, modules imported before the first paint, `escrituras.marcar`: the `store.write_json` calls to the device inside the click on a pair's checkbox, 1 in 0.7.1); (2) a moment whose median is more than 25 % **and** 30 ms slower than the base's, with the best time also more than 30 ms slower (a noisy neighbour ruins medians, not minimums); (3) a moment or count the base reaches and the PR no longer does (the driver cannot find a button: update `driver.py` in the same PR). The time targets of the spec (`[meta_ms]`) and the count targets (`[meta]`) are only reported in the job summary.
- **Ceilings are a ratchet:** a PR that lowers a count lowers its ceiling in `presupuesto.toml` (the summary says when one can drop); raising one is said in the PR description. `[techo.windows]`/`[techo.linux]` replace `[techo]` per system, because the modules imported differ.
- **Once a window is open** (the driver measures these after the open, `[meta_ms]` carries the spec's targets for Windows x64):
  - `parejas`: `catalogo-llega`, `elegir-fila` (`lista.elegir(otra, avisar=False)` and its `update()`), `elegir-pareja` (`avisar=True`: the editor loads) and `reabrir-parejas` (close «Parejas», click «Parejas…» again). The catalogue `Event` is cleared before the reopening and released after recording it, so the remote's arrival (a repaint that took over a second on 0.7.1) never lands inside the measure.
  - `ajustes`: the four panes, `pane-otra-vez` (a pane already visited) and `volver-ajustes` (from the moment the patched `wait_window` destroys «Ajustes» until the main window is quiet again).
  - `principal`: `llega-instantanea`, `marcar` (with `escrituras.marcar`), `sincronizar-ventana` (click until the pass window is viewable) and `volver-pasada` (destroying the finished pass window until the main window is quiet). The checkbox is ticked (unticked first, untimed, if it was ticked) so the selection is never empty: with nothing ticked «Sincronizar ahora» does nothing and 0.7.1 writes no empty selection.
  - **No real pass ever runs:** the driver replaces `ui.tk.orden_sync` (the pass is `python -c pass`) and `ui.tk.preguntar_resync` (answers no), and wraps `store.write_json` to count the calls under the device. Both trees look those names up in `ui.tk` at call time.
  - **The shared read** (`root.instantanea`, `root.sondeo_instantanea`, set by the main window of the PR) is collected after the first paint and after `cancel_afters(root)`: sleep (never `update()`: pumping the loop would run the module preload in the PR only and bias «Parejas»/«Ajustes») until `root.instantanea.hecho`, then time `sondeo_instantanea._mirar()` plus `root.update()`. It is collected in the three main-window flows, so «Parejas», «Ajustes» and the clicks start from the same content a 0.7.1 window has from its first paint, and only `principal` records `llega-instantanea`. A tree without those attributes (0.7.1) skips it.
  - **Every step works on both trees:** a moment only the PR has reads «nuevo» in the summary, never a failure; one the base reaches and the PR does not fails (update `driver.py` in the same PR).
- **Never a required check:** it is path-filtered and the machine varies from one run to another.
- The wizard flow, the agent flow and the main-window flows drive real buttons by their labels («Parejas…», «Ajustes…», «Sincronizar ahora», the sidebar's «Reparación», «Nombre e icono», «Actualizaciones», «Configuración»), the checkboxes by class (`ttk.Checkbutton`, the topmost visible one) and the pass window as a `Toplevel` child of the root whose title ends in «— OK»: a PR that renames or replaces one updates `driver.py`.
- **Temporary push trigger.** While the stage is developed on its branch both workflows also run on a push to it (marked `# TEMPORAL: quitar antes del PR`); remove it when the PR is opened.

## Indirection points

Everything that touches the network, a real device or the desktop is a **module-level indirection point so every test can replace it**. Keep new ones in that shape. A module imported inside a function (`ui/__init__.py`, `ui/tk.py`, `common/update.py`, `runsync.py`: `ui.md`) is patched on the module itself (`update.fetch = …`, `llavero.pasada = …`), never through the importer's namespace; the names tests do replace through another module's namespace (`runsync.ui`, `runsync.prioridad`, `runsync.model`, `ui.tk.pair_status_notes`, `ui.tk.abrir`, `uitk.mostrar`…) stay imported at module level. Registry:

- **Network and downloads**: `catalog.run()` (`fleet` and `remote_picker` go through it; it has an optional `apuntar` that no caller passes, so a stub takes just `args`; `tests/_rclone_falso.py` is a POSIX `sh` script standing in for the rclone binary, `catalog._binary = lambda: falso`, which echoes or sleeps by `$PRDRIVE_FALSO_MODO`), `update.fetch()`, `rclone_bin.fetch()`, `runtime_bin.fetch()` (also the Tk-with-Xft package; `runtime_bin.cache_dir()` too), `veracrypt_bin.fetch()`/`ensure_veracrypt()`, `keepassxc_bin.fetch()`, `descarga.esperar()`.
- **Window and desktop actions**: `icons.USAR_SVG` (a module switch, not a function: a test that needs the Python painter on a Tk 9 sets it; it gates the per-interpreter probe `icons.svg_disponible()`), `ui.abrir()`, `runsync.notificar_fallo()`, `tk.mostrar()`/`confirmar_plan()`, `tk.proteger_de_capturas()`/`tk._afinidad_de_pantalla()`, `tk.precargar()` (the background import of the screens; `tk_update` calls it right before applying an update), `tk._encubrir()`/`tk._atributo_dwm()` (`ensenar()`'s cloak and title bar; the second is the one dwmapi call), `segundo_plano.lanzar()` (tests set it to `en_el_acto()`), `tk_equipo.escritorio()`, `pairing.construir()`, `watch.resumen()`, `watch.consulta()` (a question to `schtasks`/`systemctl` with a time limit: a test returns its own `CompletedProcess`, or 124 for «no contesta»), `watch.pedir_al_agente()`/`pedir_a_la_raiz()`, `cifrado.lanzar_expulsion()`/`pedir_bloqueo()`, `_preguntar_borrado()`.
- **Files and conflicts**: `conflicts.recorrer()`, `conflict_editor.mover()`/`borrar()`, `instantanea.leer()` (the window's one read of the device, run on a thread: a test replaces it with a function returning an `Instantanea`, or calls it for real on a sandbox) and the readers it calls, each replaceable where it lives (`revision.revisar()`, `conflicts.cargar()`, `components.pendientes()`, `cifrado.expulsion()`/`bloqueo()`, `watch.resumen()`, `instantanea.estados_de()`/`linea_del_llavero()`); the stubs take `**_k`, since `leer()` passes `fisica=`.

- **Host OS**: `runsync.padre_pid()` (the parent's pid, so a test can be the old window's child), `_win_volumes()`, `_leer_estado_bitlocker()`, `store.procesos()` (under `procesos_desde()`), `store.matar_arbol()` (kills a process and its whole tree: `taskkill /F /T` on Windows, `SIGKILL` to the process group on POSIX, never raises; the caller starts the child with `start_new_session=True`, or `CREATE_NEW_PROCESS_GROUP` on Windows; `ui/tk.output_window()` cuts its pass through it and `llavero.matar_arbol()` delegates to it), `store.matar_hijos()` (kills the read children `store.correr_apuntado()` noted, which `catalog.run()` and `watch.consulta()` go through: directly, `Popen.kill()`, returns how many; a test sets it to a recorder or runs it against real sleepers, `tests/test_hijos.py`), `registro.leer()`/`escribir()`/`borrar()`/`vacia()` (HKCU).
